# Phase 8.2 — CRM Cabinet Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Give every CRM cabinet page a desktop internal layout + richer widgets (derived client-side from existing endpoints), and seed the developer-CRM data that populates them.

**Architecture:** Presentational redesign mirroring `apps/web` idioms (card-grid tiers, `lg:grid-cols-[1fr_sidebar]` main+sticky-aside, stat-card rows). Phone (<md) layout preserved via `contents` wrappers; only md/lg/desk tiers added. One additive idempotent seed block enables all pages. No backend endpoint/DTO/schema changes; no new deps; colours unchanged (blue).

**Tech Stack:** React 19, React Router 7, Tailwind v4 (@theme tokens), TanStack Query 5, FSD; Prisma seed.

**Spec:** docs/superpowers/specs/2026-09-20-phase-8.2-crm-pages-design.md (each task cites its section; the spec carries the full design rationale + data sources).

## Global Constraints

- Code/identifiers/comments English; UI copy Uzbek (keep existing strings).
- **No new test files.** Verify per task with `yarn turbo run typecheck lint build --filter=@rieltor/crm --filter=@rieltor/api` (root turbo; never `yarn workspace <pkg> lint` → exit 127). Editing existing fixtures allowed.
- **No backend endpoint/DTO/schema/migration changes.** Every widget derives from data the page already fetches (spec §Non-Goals lists the deferred backend widgets — use proxies or omit; do NOT add endpoints). Task 1 (seed) is the only `apps/api` change and touches only `prisma/` fixtures.
- **Phone (<768) layout stays intact** — add md/lg/desk tiers only; preserve source order with `contents` wrappers (as `apps/web/src/pages/complex/ui/complex-page.tsx` does).
- **Colours unchanged** — blue accent already set; status tones use `brand-green`/`brand-amber`/`brand-rose`; any bar/meter uses the blue accent, never `#6d28d9`. No charting library (pure-CSS bars only).
- BigInt money as string end-to-end; never `Number()` a som value — read sign off the string; format with `formatPriceSom(v,'SALE')`.
- Seed additive + idempotent (fixed ids + `organization.count()===0` guard); no schema change (models exist).
