# Phase 2.3 — Telegram bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A long-polling Telegram bot (nestjs-telegraf) that reuses existing services for a chat valuation, a conversational listing-creation wizard with photos, and Telegram DM delivery of the Phase 2.2 monthly notifications — dormant and harmless without a real bot token.

**Architecture:** New `apps/api/src/bot/` module. The bot is a delivery channel over `ValuationService`, `ListingsService`, and an extracted `AuthService.ensureTelegramUser`. Graceful degradation: launch is guarded in a try/catch so a placeholder token (dev/CI) leaves the bot dormant while the API boots. Notification DMs flow through a `TelegramNotifier` seam in `NotificationsModule` that the bot registers itself into at launch (one-way dependency, no cycle).

**Tech Stack:** NestJS 11 · nestjs-telegraf + telegraf · Node 22 · Prisma 6.

**Spec:** `docs/superpowers/specs/2026-08-25-phase-2.3-telegram-bot-design.md`

## Global Constraints

- Uzbek user-facing copy; **English** identifiers/comments.
- **NO new test files** ([[no-tests-unless-asked]]). Verify each task with `yarn lint`, `yarn typecheck`, and the existing suite staying green (web 34 · shared 18 · API unit 37 · e2e 22 = **111**). Run API tests with env: `set -a; source apps/api/.env; set +a`. Nest DI scratch scripts must be run via **`nest build` + compiled JS**, never `tsx` ([[ci-gotchas]] — tsx drops `design:paramtypes`).
- **Graceful degradation is the top invariant:** with a placeholder/invalid `TELEGRAM_BOT_TOKEN` (the dev/CI default), the bot MUST stay dormant and the API MUST boot with every HTTP endpoint working. The bot launch is wrapped in try/catch; the DM path is skipped when the bot isn't live. **CI already sets a placeholder token — the bot staying dormant is what keeps CI green** ([[ci-gotchas]]).
- Controllers/services keep their existing shapes; the bot depends on services, never the reverse (except the `TelegramNotifier` seam, which the bot registers into).
- Money is formatted with the shared `formatPriceSom`; BigInt values are handled as the services already do.

- [ ] **Step 1: Create `telegram-notifier.ts`:**

```ts
import { Injectable, Logger } from '@nestjs/common';

type SendFn = (telegramId: string, text: string) => Promise<void>;

/**
 * A seam so notifications can be delivered over Telegram without NotificationsModule
 * depending on the bot. The bot registers its sender at launch; until then (dev, CI,
 * no token) `send` is a no-op and only the in-app notification is written.
 */
@Injectable()
export class TelegramNotifier {
  private readonly logger = new Logger(TelegramNotifier.name);
  private sender: SendFn | null = null;

  register(send: SendFn) {
    this.sender = send;
  }

  get isActive() {
    return this.sender !== null;
  }

  async send(telegramId: string, text: string) {
    if (!this.sender) return;
    try {
      await this.sender(telegramId, text);
    } catch (error) {
      this.logger.warn(`Telegram DM failed for ${telegramId}: ${String(error)}`);
    }
  }
}
```

```ts
import { Injectable, Logger, OnModuleInit } from '@nestjs/common';
import { InjectBot } from 'nestjs-telegraf';
import { Telegraf } from 'telegraf';
import { TelegramNotifier } from '../notifications/telegram-notifier';

@Injectable()
export class BotService implements OnModuleInit {
  private readonly logger = new Logger(BotService.name);
  botReady = false;

  constructor(
    @InjectBot() private readonly bot: Telegraf,
    private readonly notifier: TelegramNotifier,
  ) {}

  async onModuleInit() {
    try {
      // launch() resolves once long-polling starts; a bad token rejects here.
      await this.bot.telegram.getMe(); // fails fast on an invalid token
      void this.bot.launch();
      this.botReady = true;
      this.notifier.register((telegramId, text) => this.bot.telegram.sendMessage(telegramId, text));
      this.logger.log('Telegram bot launched (long-polling)');
    } catch (error) {
      this.logger.warn(`Telegram bot dormant — launch skipped: ${String(error)}`);
    }
  }
}
```

/** Resolve a Telegram file_id to its bytes (for the sharp pipeline). */
export async function downloadTelegramPhoto(telegram: Telegram, fileId: string): Promise<Buffer> {
  const link = await telegram.getFileLink(fileId);
  const res = await fetch(link.toString());

}
