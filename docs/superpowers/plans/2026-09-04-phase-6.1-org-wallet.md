# Phase 6.1 — Developer/Org wallet + funded commission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each `Organization` a wallet (an org-scoped ledger mirroring the realtor `Wallet`), let a developer top it up (stub), and at booking convert→SOLD debit the owning org's wallet — in the same transaction that credits the fixated realtor — to fund the commission and stop the platform floating it. Short balance → the sale still completes, the realtor is still paid, the org wallet goes negative (a recorded debt).

**Architecture:** New `OrgWallet` + `OrgWalletTransaction` (+ `enum OrgWalletTxType { TOPUP COMMISSION_DEBIT }`), a parallel `OrgWalletService` mirroring `WalletService` (lazy ensure, atomic ledger writes, but the commission debit is unconditional — negative allowed, no 402/lock), a `crm/wallet` controller (DeveloperGuard, org-scoped) for view + stub top-up, one new `debitForCommission(tx,…)` call inside the existing `booking.act()` convert transaction, and a CRM wallet page mirroring the apps/agent realtor wallet page.

**Tech Stack:** NestJS 11 + Prisma 6 + Postgres, Zod (shared DTOs), React 19 + TanStack Query 5 (apps/crm, Feature-Sliced Design).

**Spec:** `docs/superpowers/specs/2026-09-04-phase-6.1-org-wallet-design.md`

## Global Constraints

- Uzbek user-facing copy; **English** identifiers/comments.
- **No new test files** — verify via `yarn lint`/`typecheck`/`build`, compiled-JS scratch (nest build → node; NEVER `tsx`), browser smoke. Existing suite stays green: **api 37 + e2e 22, web 34, shared 18 = 111**; `@rieltor/crm` + `@rieltor/agent` ship no tests.
- **Additive migration only** (one folder); `CREATE TYPE`/`CREATE TABLE`/`ADD CONSTRAINT` only, no `DROP`, no change to `Wallet`/`WalletTransaction`. **No new env var.**
- BigInt money is a **string** end-to-end. `amountSom` is non-negative (`/^\d+$/`, direction by `type`). **`OrgWallet.balanceSom` MAY be negative** → its DTO string allows a leading minus (`/^-?\d+$/`).
- The org commission debit is **unconditional**: no `FOR UPDATE` lock, no balance guard, NEVER a `402` — it is a plain atomic decrement, balance may go negative (contrast the realtor `debitForClaim`). It rides the existing convert `$transaction` inside the `count===1` + `commissionSom > 0n` block, so it is atomic with the SOLD flip + realtor credit and fires at most once.
- The org wallet is created lazily (P2002-safe upsert), like `ensureWallet`.
- `apps/crm` imports only `@rieltor/shared` + its own `@/*`; FSD boundaries hold.
- **`@rieltor/shared` gotcha:** api resolves shared from its built `dist` — run `yarn workspace @rieltor/shared build` before `yarn workspace @rieltor/api typecheck` after a shared edit.

### Task 1: Prisma — OrgWallet + OrgWalletTransaction + OrgWalletTxType

**Files:** Modify `apps/api/prisma/schema.prisma`; Create `apps/api/prisma/migrations/<ts>_phase_6_1_org_wallet/migration.sql`

**Interfaces:** Produces `enum OrgWalletTxType { TOPUP COMMISSION_DEBIT }`, `model OrgWallet`, `model OrgWalletTransaction`, `Organization.orgWallet OrgWallet?`.

- [ ] **Step 1: Add the enum + models** (structurally clone the existing `Wallet`/`WalletTransaction`/`WalletTxType` triple, swapping `userId`→`orgId`):

```prisma
enum OrgWalletTxType {
  TOPUP
  COMMISSION_DEBIT
}

model OrgWallet {
  id           String                 @id @default(cuid())
  orgId        String                 @unique
  org          Organization           @relation(fields: [orgId], references: [id], onDelete: Cascade)
  balanceSom   BigInt                 @default(0) // cached = sum(transactions); MAY be negative (debt)
  transactions OrgWalletTransaction[]
  createdAt    DateTime               @default(now())
  updatedAt    DateTime               @updatedAt
}

model OrgWalletTransaction {
  id          String          @id @default(cuid())
  orgWalletId String
  orgWallet   OrgWallet       @relation(fields: [orgWalletId], references: [id], onDelete: Cascade)
  type        OrgWalletTxType
  amountSom   BigInt          // always positive; direction implied by `type`
  fixationId  String?
  createdAt   DateTime        @default(now())

  @@index([orgWalletId, createdAt])
}
```

Add `orgWallet OrgWallet?` to `model Organization` (back-relation). Leave `Wallet`/`WalletTransaction` UNCHANGED.

### Task 3: OrgWalletService + crm/wallet endpoints

**Files:** Create `apps/api/src/org-wallet/org-wallet.service.ts`, `org-wallet.controller.ts`, `org-wallet.module.ts`; Modify `apps/api/src/app.module.ts`

**Interfaces:** Consumes `OrgWalletView*` DTOs (T2), `DeveloperGuard` + `DeveloperService.orgIdOf`, `TOPUP_PACKAGES`/`TopupSchema`. Produces `OrgWalletService` (exported), `GET /api/crm/wallet`, `POST /api/crm/wallet/topup`.

- [ ] **Step 1: `OrgWalletService`** (mirror `WalletService`; read `wallet.service.ts` first):
  - `ensureOrgWallet(orgId)` — `prisma.orgWallet.upsert({ where:{orgId}, create:{orgId}, update:{} })` (P2002-safe; balance defaults 0).
  - `view(orgId): Promise<OrgWalletView>` — ensure, then read the wallet + its transactions (order `createdAt desc`); map BigInt→string (`String(balanceSom)` — may be negative; `String(amountSom)`).
  - `topup(orgId, packageId): Promise<OrgWalletView>` — resolve the package amount from `TOPUP_PACKAGES`; in one `$transaction`, atomic `balanceSom: { increment }` (upsert-ensure) + create a `TOPUP` row; return `view`.
  - `debitForCommission(tx: Prisma.TransactionClient, orgId: string, amountSom: bigint, ref: { fixationId?: string }): Promise<void>` — runs on the caller's tx; **UNCONDITIONAL** (no `FOR UPDATE`, no balance guard, no 402): `const w = await tx.orgWallet.upsert({ where:{orgId}, create:{ orgId, balanceSom: -amountSom }, update:{ balanceSom: { decrement: amountSom } }, select:{ id:true } })` then `await tx.orgWalletTransaction.create({ data:{ orgWalletId: w.id, type:'COMMISSION_DEBIT', amountSom, fixationId: ref.fixationId ?? null } })`. (New wallet → created already in debt at `-amountSom`; existing → decremented; balance may go negative.)

- [ ] **Step 2: `OrgWalletController`** — `@UseGuards(JwtGuard, DeveloperGuard) @Controller('crm/wallet')` (→ `/api/crm/wallet`; do NOT use `wallet`):

```ts
@Get()
view(@CurrentUser() u) { return this.orgWallet.view(this.developer.orgIdOf(u.id) /* await */); }

@Post('topup')
topup(@CurrentUser() u, @Body() body: unknown) {
  const { packageId } = TopupSchema.parse(body);
  return this.orgWallet.topup(/* await orgIdOf */ u.id → orgId, packageId);
}
```

(Resolve `orgId` via `await this.developer.orgIdOf(u.id)`; inject `DeveloperService`. Match the existing current-user decorator + async style.)

- [ ] **Step 3: `OrgWalletModule`** — provides + **exports** `OrgWalletService` (so `DeveloperModule` can inject it in T4), imports whatever gives `DeveloperService`/`DeveloperGuard` + Prisma. Register in `app.module.ts`.

- [ ] **Step 4: Verify.** `yarn workspace @rieltor/api typecheck`. Compiled-JS scratch (nest build → node): create an org; `topup` credits it (TOPUP row, balance up); `view` returns balance + ledger; `debitForCommission(tx, orgId, X)` inside a `prisma.$transaction` decrements the balance and, from a fresh org (no wallet), creates it at `-X` (NEGATIVE, no throw); a foreign caller's `orgIdOf` resolves only their own org. `yarn workspace @rieltor/api test` (37) + `test:e2e` (22).

- [ ] **Step 5: Commit.** `git add apps/api/src/org-wallet apps/api/src/app.module.ts && git commit -m "feat(api): OrgWalletService + crm/wallet view + stub topup"`
