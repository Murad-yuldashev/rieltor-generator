# Phase 5.2 — Shaxmatka + booking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the developer CRM a shaxmatka — a status-coloured floor×unit grid on the building page with single-cell edit, multi-select bulk edit, and unit **booking** (hold a unit for a free-text client with an auto-expiring window; cancel frees it, convert marks it SOLD).

**Architecture:** A new `Booking` model (a hold on a `Unit`, org-scoped through the 5.1 ownership chain) + booking flow (book/cancel/convert/extend), an hourly expiry cron, a bulk-edit endpoint, and the `Unit` view enriched with its active booking — all in the existing `DeveloperModule`. The `apps/crm` building-detail page gains the grid + booking controls; a bookings list page is added.

**Tech Stack:** NestJS 11 + Prisma 6 + `@nestjs/schedule`, Zod (shared DTOs), React 19 + TanStack Query 5 + Vite 6 + Tailwind 4 (Feature-Sliced Design, `apps/crm`).

**Spec:** `docs/superpowers/specs/2026-09-03-phase-5.2-shaxmatka-booking-design.md`

## Global Constraints

- Uzbek user-facing copy; **English** identifiers/comments.
- **No new test files** (project rule) — verify via `yarn lint`/`typecheck`/`build`, compiled-JS scratch (nest build → node; NEVER tsx), and browser smoke. Existing suite stays green: **api 37 + e2e 22, web 34, shared 18 = 111**; `@rieltor/crm` ships no tests.
- **Additive migration only**; **no new env var**.
- Booking + bulk endpoints are **DeveloperGuard** + **org-scoped** via the unit ownership chain (`unit → building → complex → org`, the 5.1 `unitOwnedOrThrow` idiom → **404** for a foreign unit/booking). Bulk ownership is **all-or-nothing** (any foreign id → 404, no write).
- A unit has **at most one `ACTIVE` booking**; a hold is allowed only on an `AVAILABLE` unit (else **409**); the booking↔unit-status writes are **transactional** with a unit **row lock** (`SELECT … FOR UPDATE`, the 4.x claim idiom) so two concurrent holds cannot both win.
- The expiry cron is **idempotent** and frees a unit only when it is **still `BOOKED`** by the expiring hold (a hand-`SOLD` unit is left alone).
- BigInt money (`priceSom`) is a **string** end-to-end. `apps/crm` imports only `@rieltor/shared` + its own `@/*`.

async book(userId: string, unitId: string, input: BookingCreate): Promise<Booking> {
  await this.dev.assertUnitOwned(userId, unitId); // 404 if not this org's unit
  const holdUntil = new Date(Date.now() + (input.holdDays ?? DEFAULT_HOLD_DAYS) * DAY_MS);
  const booking = await this.prisma.$transaction(async (tx) => {
    await tx.$queryRaw`SELECT 1 FROM "Unit" WHERE id = ${unitId} FOR UPDATE`;
    const unit = await tx.unit.findUnique({ where: { id: unitId }, select: { status: true } });
    if (!unit) throw new NotFoundException('Xonadon topilmadi');
    if (unit.status !== 'AVAILABLE') throw new ConflictException("Xonadon bo'sh emas");

      data: {
        unitId,
        clientName: input.clientName,
        clientPhone: input.clientPhone,
        holdUntil,
        note: input.note ?? null,
        createdById: userId,
      },
    });
    await tx.unit.update({ where: { id: unitId }, data: { status: 'BOOKED' } });
    return b;
  });

}

- [ ] **Step 1: `BookingService.expireOverdue`** — free overdue holds, leaving hand-progressed units alone:

```ts
/** Expire ACTIVE bookings past holdUntil; free a unit only if it is STILL BOOKED. */
async expireOverdue(): Promise<{ expired: number }> {
  const now = new Date();
  const overdue = await this.prisma.booking.findMany({
    where: { status: 'ACTIVE', holdUntil: { lt: now } },
    select: { id: true, unitId: true },
  });
  for (const b of overdue) {
    await this.prisma.$transaction([
      this.prisma.booking.update({ where: { id: b.id }, data: { status: 'EXPIRED' } }),
      this.prisma.unit.updateMany({
        where: { id: b.unitId, status: 'BOOKED' }, // only free a still-BOOKED unit
        data: { status: 'AVAILABLE' },
      }),
    ]);
  }
  return { expired: overdue.length };
}
```

- [ ] **Step 1: `bulkUpdateUnits`** — org-scoped ownership all-or-nothing, price to all, status skips active-booked:

```ts
async bulkUpdateUnits(userId: string, input: UnitBulkUpdate): Promise<{ updated: number; skippedBooked: number }> {
  const orgId = await this.orgIdOf(userId);
  const owned = await this.prisma.unit.count({
    where: { id: { in: input.unitIds }, building: { complex: { orgId } } },
  });
  if (owned !== input.unitIds.length) throw new NotFoundException('Xonadon topilmadi'); // foreign/missing id
  const priceSom = input.priceSom !== undefined ? BigInt(input.priceSom) : undefined;
  let skippedBooked = 0;
  if (input.status !== undefined) {
    // status must NOT strand an ACTIVE hold: skip units that have one.
    const bookedIds = (
      await this.prisma.unit.findMany({
        where: { id: { in: input.unitIds }, bookings: { some: { status: 'ACTIVE' } } },
        select: { id: true },
      })
    ).map((u) => u.id);
    skippedBooked = bookedIds.length;
    const statusIds = input.unitIds.filter((id) => !bookedIds.includes(id));
    await this.prisma.unit.updateMany({
      where: { id: { in: statusIds } },
      data: { status: input.status, ...(priceSom !== undefined ? { priceSom } : {}) },
    });
    if (priceSom !== undefined && bookedIds.length) {
      // price still applies to the skipped booked units
      await this.prisma.unit.updateMany({ where: { id: { in: bookedIds } }, data: { priceSom } });
    }
  } else {
    await this.prisma.unit.updateMany({ where: { id: { in: input.unitIds } }, data: { priceSom: priceSom! } });
  }
  return { updated: input.unitIds.length - (input.status !== undefined ? 0 : 0), skippedBooked };
}
```

Simplify the return to that. Price always applies to all owned ids; `skippedBooked` counts units whose STATUS was skipped.)
