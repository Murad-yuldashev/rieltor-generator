# Phase 5.4 — Cross-CRM fixation (C6) + commission (C7/C8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a realtor fixate their claimed NEW_BUILD lead onto a developer's unit (C6, uniqueness-checked), and pay that realtor a commission to their wallet the moment the unit's booking converts to SOLD (C7/C8), matched by canonicalized phone.

**Architecture:** A new `Fixation` model bridging `PropertyRequest.claimedById` (the realtor) + `Unit` + the buyer's canonical phone. A realtor `POST /api/leads/:id/fixate` (FOR UPDATE uniqueness). Commission fires inside a **made-atomic** `booking.act()` convert transaction: match the booking's phone to an ACTIVE fixation, compute `priceSom × bps / 10000`, and credit the realtor's wallet via a new `WalletTxType.COMMISSION`. Commission rate is per-Complex default + per-Unit override (basis points). Realtor cabinet surfaces the target unit + estimated commission on the claimed lead; CRM sets the rate + shows a fixation indicator.

**Tech Stack:** NestJS 11 + Prisma 6 + Postgres, Zod (shared DTOs), React 19 + TanStack Query 5 (apps/agent realtor cabinet, apps/crm developer CRM, Feature-Sliced Design).

**Spec:** `docs/superpowers/specs/2026-09-04-phase-5.4-fixation-commission-design.md`

## Global Constraints

- Uzbek user-facing copy; **English** identifiers/comments.
- **No new test files** — verify via `yarn lint`/`typecheck`/`build`, compiled-JS scratch (nest build → node; NEVER `tsx`), browser smoke. Existing suite stays green: **api 37 + e2e 22, web 34, shared 18 = 111**; `@rieltor/crm` + `@rieltor/agent` ship no tests.
- **Additive migration only** (one folder); `CREATE TYPE`/`CREATE TABLE`/`ADD COLUMN`/`ADD CONSTRAINT`/`ALTER TYPE … ADD VALUE` only, no `DROP`, no existing column altered. A newly-added enum value must NOT be written in the same migration (Postgres). **No new env var.**
- BigInt money (`priceSom`, `commissionSom`, `amountSom`, `balanceSom`) is a **string** end-to-end (`/^\d+$/`). Commission math is BigInt: `(priceSom ?? 0n) * BigInt(bps) / 10000n` (truncates toward zero — the documented rounding). `priceSom` is nullable → null yields 0 commission.
- Commission fires ONLY at `booking.act()` convert, made **atomic** (`updateMany where status:'ACTIVE'`, credit only when `count===1`) so a concurrent/re-fired convert cannot double-credit. cancel/extend/expire never pay.
- Fixation uniqueness ("one ACTIVE per (unitId, buyerPhone)") is enforced **in-code** via `SELECT … FOR UPDATE` on the unit (the 4.1 claim idiom), NOT a DB partial-unique.
- Phones are matched via a shared `canonicalizePhone()` → `998XXXXXXXXX` applied to BOTH `User.phone` (already canonical) and the free-text `Booking.clientPhone`.
- Auth: fixate/unfixate = `RealtorGuard`; commission config = `DeveloperGuard` + org-scope (foreign → 404); convert = `DeveloperGuard` (existing).
- **`@rieltor/shared` gotcha:** api resolves shared from its built `dist` — run `yarn workspace @rieltor/shared build` BEFORE `yarn workspace @rieltor/api typecheck` after any shared edit.

```ts
// Credit the realtor's wallet on a caller-owned transaction (atomic increment + ledger row).
async credit(
  tx: Prisma.TransactionClient,
  userId: string,
  amountSom: bigint,
  ref: { fixationId?: string } = {},
): Promise<void> {
  await tx.wallet.update({ where: { userId }, data: { balanceSom: { increment: amountSom } } });
  await tx.walletTransaction.create({
    data: { walletUserId: userId /* match the real FK field */, type: 'COMMISSION', amountSom, fixationId: ref.fixationId ?? null },
  });
}
```

Match the real `WalletTransaction` relation/field names (check the model). Update the wallet view mapper to surface `fixationId` if it maps `leadId`.

- [ ] **Step 3: `cancelFixation(userId, leadId)`** — find the lead's ACTIVE Fixation with `realtorId === userId` (404 if none); set `status:'CANCELLED'`, `cancelledAt`. Return `toFixation`.

- [ ] **Step 4: Controller routes** on the `JwtGuard + RealtorGuard` `leads.controller`:

```ts
@Post(':id/fixate')
fixate(@CurrentUser() user, @Param('id') id: string, @Body() body: unknown) {
  const { unitId } = FixateInputSchema.parse(body);
  return this.fixations.fixate(user.id, id, unitId);
}
@Delete(':id/fixate')
unfixate(@CurrentUser() user, @Param('id') id: string) {
  return this.fixations.cancelFixation(user.id, id);
}
```
