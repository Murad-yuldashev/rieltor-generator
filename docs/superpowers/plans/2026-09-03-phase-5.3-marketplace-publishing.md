# Phase 5.3 — Marketplace publishing (A12 ЖК pages + verified developer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a verified developer publish a Complex from `/crm` so it appears on the public marketplace as a ЖК page (live per-unit availability, verified-developer badge, cover+gallery, map pin); a buyer's inquiry becomes a scored `PropertyRequest` lead in the realtor pipeline.

**Architecture:** Additive Prisma (publish state + org `verified` + `ComplexImage` + `PropertyRequest.complexId/unitId`). New public `@Controller('jk')` (unguarded read + JwtGuard inquiry) mirroring `realtor-public`; a moderator `moderation/developers` verify flow mirroring `realtor-moderation`; developer-side publish/verification-request/image endpoints in `DeveloperModule`. New `apps/web` `/jk` browse+detail pages and a `/moderation/developers` queue; `apps/crm` publish + media + verification-request controls.

**Tech Stack:** NestJS 11 + Prisma 6 + `sharp` (image pipeline), Zod (shared DTOs), React 19 + TanStack Query 5 + React Router 7 + Vite 6 + Tailwind 4 (Feature-Sliced Design, `apps/web` + `apps/crm`).

**Spec:** `docs/superpowers/specs/2026-09-03-phase-5.3-marketplace-publishing-design.md`

## Global Constraints

- Uzbek user-facing copy; **English** identifiers/comments.
- **No new test files** (project rule) — verify via `yarn lint`/`typecheck`/`build`, compiled-JS scratch (nest build → node the compiled JS; NEVER `tsx`), and browser smoke. The existing suite stays green: **api 37 + e2e 22, web 34, shared 18 = 111**; `@rieltor/crm` ships no tests.
- **Additive migration only** — one folder `<ts>_phase_5_3_marketplace_publishing`; `CREATE TYPE`/`CREATE TABLE`/`ADD COLUMN`/`ADD CONSTRAINT` only, no `DROP`, no existing column altered. **No new env var.**
- BigInt money (`priceSom`, `priceFromSom`) is a **string** end-to-end (`/^\d+$/`).
- Public reads are **unguarded** and hard-filter `publishStatus='PUBLISHED'`; they leak **no** internal ids/`orgId` and **no** booking rows (client PII). The inquiry write is `JwtGuard` (method-level). Developer-side writes are `DeveloperGuard` + org-scoped (foreign complex → **404**, the 5.1 `complexOwnedOrThrow` idiom). Moderator routes are `RolesGuard @Roles('MODERATOR','ADMIN')`.
- Verified is **Organization-level**, moderator-granted. Publish is a developer self-service `DRAFT↔PUBLISHED` toggle, gated on `org.verified` **and** a completeness check.
- Image reuse is at **`process-image.ts::processImage`** only (model-agnostic); `ListingsService.addImage*` is Listing-coupled and NOT reused.
- `apps/web`/`apps/crm` import only `@rieltor/shared` + their own `@/*`; FSD eslint boundaries hold (feature widgets injected as `ReactNode` slots, never imported upward).

```ts
// Kebab-slug from an arbitrary name, matching the realtor-slug regex shape.
export function slugify(input: string): string {
  const base = input
    .toLowerCase()
    .normalize('NFKD')
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '')
    .slice(0, 38);
  return base.length >= 3 ? base : `jk-${base}`.slice(0, 40);
}
```

- [ ] **Step 2: Unique-slug resolver in the service.** Add a private helper that, given a candidate, appends `-2`, `-3`, … until no other `Complex.slug` collides (exclude the current complex id):

```ts
private async uniqueComplexSlug(name: string, selfId: string): Promise<string> {
  const baseSlug = slugify(name);
  for (let n = 1; ; n++) {
    const candidate = n === 1 ? baseSlug : `${baseSlug}-${n}`.slice(0, 40);
    const clash = await this.prisma.complex.findFirst({
      where: { slug: candidate, NOT: { id: selfId } },
      select: { id: true },
    });
    if (!clash) return candidate;
  }
}
```
