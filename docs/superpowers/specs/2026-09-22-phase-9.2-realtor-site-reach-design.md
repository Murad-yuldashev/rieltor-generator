# Phase 9.2 — Realtor Site Reach: Custom Domain + YML Feed + iframe Embed — Design

**Status:** design (spec) — awaiting review
**Date:** 2026-09-22
**Branch:** `claude/phase-9.2-realtor-site-reach` (off master `67c44dd`)
**Spec context:** finishes the deferred half of Phase 9 (C1) and adds C2 ("Каталог.ПРО / База.ПРО"). Phase 9 shipped the branded, subscription-gated realtor catalogue site at `/r/:slug`. Phase 9.2 extends its **reach**: the realtor's own domain, a syndication feed for other portals, and an embeddable widget for external sites.

## Goal

Let a realtor's Phase-9 site reach beyond `/r/:slug` in three ways: (1) serve it on the realtor's **own custom domain** (`ali.uz`) with a DNS-verification flow; (2) export the catalogue as a **Yandex Realty YML feed** for syndication to other portals; (3) offer an **iframe embed widget** external sites paste in. All three reuse the Phase-9 site data + gating.

## Architecture

The Phase-9 realtor site is served by `apps/api/src/ssr` (`SsrController` owns `/`; `NotFoundShellFilter` serves `/r/:slug` with realtor SSR meta via `RealtorPublicService.getSiteMeta`) and rendered by `apps/web` `RealtorPage`, gated by `SubscriptionService.isActive` + `sitePublished` (`siteActive`). Phase 9.2 builds on that spine:

- **Custom domain** is host-based routing. A NestJS middleware (behind the existing `trust proxy`) reads `req.hostname`; when it is NOT the canonical `PUBLIC_BASE_URL` host and matches a **verified** `RealtorProfile.customDomain`, it attaches `req.realtorSlug`. The `/` shell then serves the realtor site (realtor SSR meta + an injected `window.__REALTOR_SITE__` bootstrap) instead of the marketplace, and the web SPA renders `RealtorPage` at `/` on that host. **TLS/DNS is a documented operator step** (Netlify domain-alias or a reverse proxy forwards the `Host` header — `serverless-http` + `trust proxy` already expose it); no SSL is provisioned in-app.
- **YML feed** and **embed** are new public routes on the existing `@Controller('r')` / `NotFoundShellFilter`, reusing `getSiteMeta`/the catalogue query and the `siteActive` gate.

## Tech Stack

React 19, React Router 7, Tailwind v4 (`--color-accent`/`--brand` CSS-var theming), TanStack Query 5, FSD; apps/api NestJS + Prisma 6 (one additive migration), Node built-in `node:dns/promises` (no new dep), the existing `serverless-http` Netlify function.

## Global Constraints

- Code/identifiers/comments **English**; UI copy **Uzbek**.
- **No new test files.** Verify with root turbo `yarn turbo run typecheck lint build --filter=@rieltor/web --filter=@rieltor/agent --filter=@rieltor/api` (never `yarn workspace <pkg> lint` — exit 127); plus a live browser + curl smoke. Editing the existing seed is allowed.
- **Additive migration only** — three new nullable/defaulted `RealtorProfile` columns. No drops/type-changes. BigInt money stays a **string** (never `Number()` a `priceSom`).
- **No new runtime dependencies** — `node:dns/promises` is built in; `serverless-http` already wraps the Netlify function; no XML library (build the YML string directly, XML-escaping text).
- **`brandColor`/theme is data → CSS custom property only** (XSS discipline; server hex-validates). Any host/domain value is validated (lowercase hostname regex) and never reflected into HTML/CSS unescaped.
- **Routing trap:** `r` is BOTH `@Controller('r')` (methods live under the `/api` global prefix) and the public SPA/SSR path (`/r/:slug`, served by `NotFoundShellFilter` since `r ∉ SPA_ROUTES`). So the data/asset endpoints are `@Controller('r')` methods at `/api/r/:slug/feed.xml` and `/api/r/:slug/widget.js`, while the HTML `/r/:slug/embed` is a `NotFoundShellFilter` branch — **none are added to `SPA_ROUTES`**.
- **Gating preserved:** the custom-domain site, the feed, and the embed all require `siteActive` (`role==='REALTOR' && isActive(sub) && sitePublished`); a known-but-inactive realtor never 404s the base `/r/:slug` (Phase-9 invariant), and the custom-domain host falls back only when unverified/inactive.
- **Privacy:** host resolution matches only a **verified** `customDomain` (an unverified/attacker-claimed domain never serves another realtor's site); the feed/embed leak no internal fields (same discipline as `/api/r/:slug`).
- `apps/crm` and unrelated apps are **not touched**.

## Non-Goals (this phase — explicitly deferred)

- **In-app SSL/TLS provisioning** — TLS is the platform's (Netlify domain alias / a reverse proxy with on-demand TLS). The spec documents the operator DNS/TLS steps; the app only does host→realtor resolution + serving.
- **Multiple custom domains per realtor** (one `customDomain` this phase), domain transfer/renewal automation, or a registrar integration.
- **Feed formats beyond Yandex Realty YML** (no Avito/CIAN/generic RSS this phase), and no feed for the developer CRM.
- **Inline (non-iframe) embed**, embed analytics/impression tracking, and per-embed theming beyond the site's `brandColor`.
- **Marketplace/home changes** — the canonical host keeps serving the marketplace exactly as today.

## Section 0 — Data model (`RealtorProfile` additive columns)

Additive Prisma migration (all nullable/defaulted; no existing-column changes):

- `customDomain String? @unique` — the realtor's apex host, stored lowercased without scheme/port (e.g. `ali.uz`); `@unique` so two realtors can't claim the same host.
- `customDomainVerified Boolean @default(false)` — flipped true only after the DNS TXT check passes; only a verified domain serves the site.
- `customDomainToken String?` — the random verification token the realtor publishes as a DNS TXT record; regenerated when the domain changes.

No other model changes. Shared Zod: `RealtorProfileSchema` (cabinet read) gains `customDomain: string|null`, `customDomainVerified: boolean`, `customDomainToken: string|null`; `RealtorProfileUpdateSchema` does **not** carry these (set only via the dedicated domain endpoints — Section 3). `PublicRealtorSchema` does **not** carry them (internal). A new `RealtorDomainSetSchema { domain: string }` (validated lowercase hostname) for the set-domain endpoint.

## Section 1 — Host resolution middleware + apex serving (`apps/api`)

- **`RealtorHostMiddleware`** (a NestJS middleware registered app-wide, after `trust proxy`): reads `req.hostname`. If it equals the canonical host (derived from `PUBLIC_BASE_URL`) or a localhost/preview host → no-op. Otherwise look up `RealtorProfile` by `{ customDomain: req.hostname, customDomainVerified: true }`; on a hit, attach `req.realtorSlug = profile.slug` (and short-cache the host→slug map in-process to avoid a DB hit per asset request, TTL ~60s — the in-process `Map` pattern already used by `ViewsService.lastSeen` / `RealtorPublicService.inquiryHits`). Static assets + `/api/*` pass through unaffected (they're host-agnostic).
- **Serving on a resolved host:** every shell-serving response injects a bootstrap `<script>window.__REALTOR_SITE__={"slug":"<slug>"}</script>` (JSON-escaped, via `HtmlCacheService.injectMeta`'s existing `OG_MARKER`/`</head>` mechanism) when `req.realtorSlug` is set — so a deep link like `https://ali.uz/obj/123` also boots the SPA in realtor mode, not just `/`:
  - `SsrController.shell()` (`/`) and the `NotFoundShellFilter` fallthrough (any unlisted path) serve the **realtor site** meta — `buildRealtorMetaTags(getSiteMeta(slug), slug, baseUrl)`, reused from Phase 9.
  - `SsrController.listing()` (`/obj/:id`) keeps its **listing** meta (`buildMetaTags(listing, baseUrl)` — already an `injectMeta` call today) and just adds the bootstrap.
  - When `req.realtorSlug` is unset, all three serve the marketplace exactly as today.
- **Per-request `baseUrl`:** on a resolved host the caller passes `baseUrl = https://<req.hostname>` (not `PUBLIC_BASE_URL`) so OG/canonical/JSON-LD point at the realtor's own domain; `buildRealtorMetaTags`/`buildMetaTags`/`getSiteMeta` already take `baseUrl` as an argument.

## Section 2 — Web SPA apex bootstrap (`apps/web`)

- **`RealtorPage` slug override:** `RealtorPage` currently reads `slug` from `useParams()`. Add an optional `slug?` prop; when provided (apex render) it wins, else `useParams`. All internal links stay relative (`/obj/:id`, hash anchors) so they resolve on the custom host.
- **Apex router branch:** where the app builds/provides the router (`apps/web/src/app/providers.tsx` / `router.tsx`), read `window.__REALTOR_SITE__` once at startup. The bootstrap carries `{ slug, mode? }`:
  - default (apex site) → a **minimal realtor router** — `{ path: '/', element: <RealtorPage slug={bootstrap.slug} /> }`, `{ path: '/obj/:id', element: <ListingPage /> }`, `{ path: '*', element: <RealtorPage slug={bootstrap.slug} /> }` — instead of the full marketplace `router`.
  - `mode: 'embed'` (Section 5) → a **single-route embed router** — `{ path: '*', element: <RealtorEmbed slug={bootstrap.slug} /> }`.
  - absent → the existing marketplace `router`, unchanged. (The marketplace bundle is unchanged; a resolved host just mounts a different route tree.)
- Read `window.__REALTOR_SITE__` defensively (typed accessor, try/catch, absent → marketplace) so a missing/garbled bootstrap degrades to the normal app.

## Section 3 — Domain-verification cabinet flow (`apps/agent` + `apps/api`)

- **Endpoints** (JwtGuard + RealtorGuard, on the agent profile controller):
  - `POST /api/agent/profile/domain` `{ domain }` — validates the lowercase hostname (not the platform's own host, not already claimed → 409 on `@unique`), stores `customDomain`, generates a fresh `customDomainToken` (random hex), sets `customDomainVerified=false`. Returns the profile + the TXT record to publish.
  - `POST /api/agent/profile/domain/verify` — runs `dns.promises.resolveTxt('_rieltor-verify.' + customDomain)` and, if any record equals `customDomainToken`, sets `customDomainVerified=true`. Returns the updated status (verified / still-pending with the expected record).
  - `DELETE /api/agent/profile/domain` — clears `customDomain`/`token`/`verified`.
- **Cabinet UI** (`/profile`, extend the Phase-9 "Ommaviy sahifangiz" section): a domain input + the required DNS records shown for copy (`CNAME <domain> → <platform target>` for routing + `TXT _rieltor-verify.<domain> → <token>` for ownership), a "Tekshirish" button (calls verify), and the live state (Tasdiqlanmagan / Tasdiqlangan → "Sayt <domain> manzilida"). Copy explains the operator TLS step (point DNS at the platform; TLS is issued by the platform). Hooks mirror the Phase-9 `useSaveProfile` pattern (`useSetDomain`/`useVerifyDomain`/`useClearDomain`).

## Section 4 — Yandex Realty YML feed (`apps/api`)

- **`GET /api/r/:slug/feed.xml`** (public method on `@Controller('r')`; `content-type: application/xml; charset=utf-8`): resolve the realtor by slug, require `siteActive` (else 404/empty per the gate), and emit a Yandex Realty YML document:
  - Root `<realty-feed>` with `generation-date` (ISO) and per-offer `<offer internal-id="...">`.
  - Query the realtor's PUBLISHED listings **directly from `Listing`** (not the `ListingSummary` DTO — the feed needs `areaM2`, full description, and all image URLs, which the summary omits): `type`/`deal` → YML `type` (`продажа`/`аренда`) + `category` (from `ListingType`), `priceSom` (BigInt→string) → `<price><value>…</value><currency>UZS</currency></price>`, rooms → `<rooms>`, `areaM2` → `<area>`, `floor` → `<floor>`, district/landmark/lat/lng → `<location>`, images → `<image>` absolute URLs (large 1200 variant), description → `<description>`, and `<url>` = the canonical listing URL (custom domain when set + verified, else `PUBLIC_BASE_URL/obj/:id`).
  - **XML-escape every text value** (`& < > " '`); no XML library — build the string with a small `escapeXml` helper (like the unicode/entity escaping already in `meta.ts`).
- Cabinet shows the feed URL (copyable) in the "Ommaviy sahifangiz" section, gated on `siteActive`.

## Section 5 — iframe embed page + widget script (`apps/web` + `apps/api`)

- **`/r/:slug/embed`** — a minimal, iframe-safe branded catalogue. Served by a `NotFoundShellFilter` branch (like `/r/:slug`) so it gets realtor SSR meta + the bootstrap `<script>window.__REALTOR_SITE__={"slug":"<slug>","mode":"embed"}</script>`. In `apps/web`, a lightweight **`RealtorEmbed`** component (reusing the Phase-9 catalogue section) renders ONLY the branded catalogue (no hero/contact/reviews chrome, no bottom nav), themed by `brandColor`, links opening `target="_blank"` to the realtor's site. Response headers allow framing for this path only (do not send `X-Frame-Options: DENY`; a permissive `Content-Security-Policy: frame-ancestors *`) — the canonical marketplace shell keeps its default (non-embeddable) headers.
- **`GET /api/r/:slug/widget.js`** (public method on `@Controller('r')`; `content-type: application/javascript`): returns a tiny script that, when included by an external site, injects a responsive `<iframe src="https://<host>/r/:slug/embed">` at the script's location (auto-height via `postMessage` from the embed page, with a sane default height fallback). The embed page posts its content height; the widget script listens and resizes. No external deps, no tracking.
- Cabinet shows the copy-paste embed snippet (`<script src="https://<host>/api/r/:slug/widget.js" async></script>`), gated on `siteActive`.

Extend `seedRealtorCabinet` (`apps/api/prisma/seed-realtor.ts`, additive/idempotent): give the seed realtor a **verified** custom domain so host-routing + the feed/embed demo without a real DNS setup — set `customDomain: 'aziz-rieltor.uz'` (a placeholder host a tester can add to `/etc/hosts` → localhost for the smoke), `customDomainVerified: true`, `customDomainToken: '<fixed hex>'`. The realtor already owns 8 PUBLISHED listings (Phase 9), so the feed + embed catalogue populate. Keep it additive + idempotent (the `subscription.count()` guard).
