# Phase 3.3a — Public realtor profile + site generator design

_Date: 2026-08-27 · Branch: `claude/phase-3.3a-realtor-public-profile` · Base: master `feaf3e7` · Part of: Phase 3 (Product C) · Depends on: 3.1 (RealtorProfile), 3.2 (public-page pattern)_

## 1. Goal

A public realtor **microsite** at `/r/:slug` (SSR + og-preview) showing the realtor's **branded**
profile (logo, brand colour, **verified badge**) plus their auto-updating **published-listings
catalogue**; a MODERATOR-set **verification** badge; and the marketplace's "who is selling"
display **connected to real realtor profiles** (the piece deliberately deferred from 3.1/3.2).
This is Product C's **C1 (site generator, path-based)** + **C14 (verified public profile)**.
The **rating/reviews** half of C14 is Phase **3.3b**.

## 2. Scope

1. **RealtorProfile additions:** `slug` (unique public URL), `verified`, `logoUrl`, `brandColor`.
2. **Public `/r/:slug` microsite** in `apps/web` (SSR shell + og-meta via `NotFoundShellFilter`,
   exactly like `/p/:token`) + `GET /api/r/:slug` (public).
3. **Verification:** a MODERATOR/ADMIN endpoint to set `verified` + a minimal moderator list; the
   badge renders on `/r/:slug` and on the marketplace.
4. **Marketplace connection:** the listing seller display resolves to the real realtor when the
   listing's owner is a published REALTOR (in the `toListingDetail`/`toListingSummary` mappers);
   `AgentSchema` gains `verified` + `profileSlug`.
5. **Branding editor** (cabinet, `apps/agent`): `slug` (uniqueness + reserved denylist), **logo
   upload** (`processImage`), `brandColor`, and the public-page link — extending the 3.1 profile page.

### Non-goals

- **Subdomain** (`ali.domen.uz`) — path-based `/r/:slug` for MVP; a subdomain is a production
  reverse-proxy/DNS mapping later, no code change to the page itself.
- **Reviews + rating** (the rating half of C14) — Phase **3.3b** (the profile page reserves a spot
  for the aggregate).
- Custom domain, real payment (Click/Payme) — later.
- **Subscription gating of the public page:** the public `/r/:slug` + `GET /api/r/:slug` and the
  verified badge **stay up regardless of subscription** (public marketing presence, consistent with
  sent presentations); **editing** the profile/branding requires an active subscription (RealtorGuard).
- No new contact/reveal mechanism at the profile level — the catalogue listings carry the existing
  per-listing reveal CTA; the profile header is branding + identity only.

## 3. Data model (Prisma)

Additions to the existing `RealtorProfile` (3.1) — no other model changes:

```prisma
model RealtorProfile {
  // ... existing: id, userId @unique, user, agency, bio?, regions[], experienceYears?, createdAt, updatedAt
  slug       String?  @unique          // public URL id; null = not yet published
  verified   Boolean  @default(false)  // set by MODERATOR/ADMIN
  logoUrl    String?                    // uploaded logo (processImage output)
  brandColor String?                    // hex accent for the microsite
}
```

`slug` nullable + unique: a realtor without a slug has no public page yet; setting it in the cabinet
"publishes" the microsite. `verified` defaults false. Migration is additive.

## 4. Public microsite

**API — `GET /api/r/:slug`** (public, unauthenticated, slug-gated, NOT subscription-gated):
returns `PublicRealtor` = `{ name, agency, bio, regions, experienceYears, logoUrl, brandColor,
verified, listings: ListingSummary[] }` where `listings` are the realtor-owner's **PUBLISHED**
listings (via `toListingSummary`), newest first. `name` = `User.name` (fallback "Rieltor").
`NotFoundException` on unknown slug. No `userId`/`slug`-internals leaked beyond what's client-facing.

**Page — `apps/web` `/r/:slug`** (mirrors the `/p/:token` mechanism exactly):

- Served via `NotFoundShellFilter` — a `/^\/r\/([^/]+)\/?$/` GET branch that injects og-meta and
  returns 200 (or a 404 shell on unknown slug). **NOT** added to the `setGlobalPrefix` exclude
  (that would collide with the `@Controller('r')` API path, same lesson as `/p/:token`). Add
  `buildRealtorMetaTags(...)` to `ssr/meta.ts` (mirror `buildPresentationMetaTags`): `og:title` =
  `${name} · ${agency}`, `og:image` = `logoUrl` (absolute) or the first listing image, `og:description`
  = a short bio/`${listings.length} e'lon`, `og:url` = `${baseUrl}/r/${slug}`.
- The SPA route `/r/:slug` (outside `TabLayout`, full-screen public) → `RealtorPage`: fetch
  `GET /api/r/:slug`, render the **branded header** (logo, name, agency, the **verified badge**,
  bio, regions, experience, `brandColor` as the accent) + the **catalogue** (the marketplace listing
  card, each → `/obj/:id`). A reserved (empty) area for the 3.3b rating. 404 state for an unknown slug.

## 5. Marketplace connection (careful)

Currently the public seller comes from the `Agent` model (`Listing.agentId`, all `DEFAULT_AGENT_ID`).
In `apps/api/src/listings/mapper.ts` (`toListingDetail` / `toListingSummary`), resolve the seller
**conditionally** — the listing queries must `include` `owner: { include: { realtorProfile: true } }`:

- **If** `listing.owner?.role === 'REALTOR'` **and** `owner.realtorProfile?.slug != null` (a published
  realtor) → seller = `{ name: owner.name ?? 'Rieltor', agency: profile.agency, photoUrl:
profile.logoUrl ?? owner.photoUrl ?? <default>, phoneMasked: mask(owner.phone), telegram: <as today>,
verified: profile.verified, profileSlug: profile.slug }`.
- **Else** → the existing `Agent` model exactly as today, with `verified: false, profileSlug: null`.

`AgentSchema` (public seller) gains **`verified: z.boolean()`** + **`profileSlug: z.string().nullable()`**
— **always populated** (default `false`/`null`), so no existing serialization breaks. The listing-detail
seller panel renders a **verified badge** + a "Rieltor sahifasi" link to `/r/:slug` when `profileSlug`
is set; the result-row/card show the verified badge. Seed listings (`DEFAULT_AGENT_ID`, no realtor
owner) are unchanged.

## 6. Verification

- `PATCH /api/moderation/realtors/:userId` body `{ verified: boolean }` — guarded by the existing
  `RolesGuard` + `@Roles('MODERATOR', 'ADMIN')`; sets `RealtorProfile.verified`. `GET /api/moderation/realtors`
  → the realtor profiles (name, agency, slug, verified) for the moderator list.
- **Moderator UI** (`apps/web`, reuse the existing moderation area): a minimal "Rieltorlar" list with a
  verify/unverify toggle per realtor. Keep it minimal — the endpoint + list + toggle.
- The badge renders wherever the profile appears (the `/r/:slug` header and the marketplace seller panel/card).

## 7. Branding editor (cabinet, `apps/agent`)

Extend the 3.1 profile page (`RealtorGuard`, active subscription):

- **`slug`** — an editable field ("Sizning sahifangiz: `/r/[slug]`"), auto-suggested from the name/agency,
  validated: lowercase kebab, `[a-z0-9-]`, length bounds, a **reserved denylist** (`search`, `new`, `obj`,
  `p`, `r`, `favorites`, `contact`, `offer`, `api`, `agent`, …), and **uniqueness** (the `@unique` → a
  `409`/"band" on collision). Setting it publishes the page.
- **Logo upload** — `POST /api/agent/profile/logo` (multipart, RealtorGuard) → `processImage` → `logoUrl`
  (reuse the listing image pipeline; a single logo, replace-on-reupload).
- **`brandColor`** — a colour input (hex), stored on the profile.
- A **"Ommaviy sahifangiz"** section: the `/r/:slug` link + open/preview (once the slug is set), and the
  verified badge if verified.
  The existing agency/bio/regions/experienceYears editing (3.1) stays; the profile `PATCH` (3.1) extends to
  accept `slug`/`brandColor` (with the slug validation above); logo is its own multipart endpoint.

## 8. Modules & wiring

- `apps/api`: a new `PublicRealtorController` (`@Controller('r')` → `/api/r/:slug`, public, `@ApiExcludeController()`)
  - a `RealtorPublicService` (or extend `ProfileService`) for `getBySlug`; the `moderation` module gains the
    realtor verify endpoint + list; the `agent`/profile service extends for `slug`/`brandColor`/logo; the listings
    `mapper` + the listing query `include` change (Section 5); `ssr.controller`/`not-found-shell.filter`/`meta.ts`
    gain the `/r/:slug` serving. `SsrModule`/the filter import whatever provides `getBySlug`.
- `apps/web`: the `/r/:slug` `RealtorPage` + the moderator realtor list; the listing seller panel/card gain the
  badge + profile link.
- `apps/agent`: the extended profile page (slug/logo/brandColor + public-page link).
- Shared Zod DTOs (`PublicRealtor`, the profile-update additions, the `AgentSchema` additions, the moderator
  realtor row).

## 9. Constraints

- Uzbek user-facing copy; **English** identifiers/comments ([[english-code-only]]).
- **No new test files** ([[no-tests-unless-asked]]); the existing **111**-suite stays green — the `AgentSchema`
  additions are always-populated so listing serialization/tests don't break (verify the listing unit/e2e/web
  tests early). Verify with `yarn lint`/`typecheck`/`build` (4 workspaces) + a browser smoke.
- **No new env var** — `PUBLIC_BASE_URL` builds the `/r/:slug` URL; the image pipeline exists.
- Public `/r/:slug` + `GET /api/r/:slug` are unauthenticated, slug-gated, **NOT subscription-gated**;
  editing/branding + logo + verify are guarded (RealtorGuard / MODERATOR). The public page survives a lapsed
  subscription.
- **Do not break** the marketplace: the seller resolution is additive and defaults to today's `Agent` for any
  non-published-realtor listing; SSR og-meta for `/obj/:id` is unchanged.
- FSD / Nest boundaries: `apps/agent` never imports `apps/web`; the microsite reuses the marketplace card.

## 10. Verification

- Automated: `yarn lint`/`typecheck`/`build` clean (api/shared/web/agent); **111** suite green (esp. the listing
  tests after the `AgentSchema` change); additive migration.
- API (compiled-JS scratch, [[ci-gotchas]]): set a realtor's `slug`/`brandColor`/`logoUrl`; `GET /api/r/:slug`
  (no auth) returns the profile + their PUBLISHED listings; unknown slug → 404; a listing owned by that realtor
  serializes with `verified`/`profileSlug` set (a non-realtor listing keeps the default Agent); the MODERATOR
  verify endpoint flips `verified` and a USER/realtor is 403; `GET /api/r/:slug` works with the realtor's
  subscription EXPIRED.
- Web/agent (browser smoke): a realtor sets slug + uploads a logo + brand colour → `/r/:slug` renders the branded
  header + catalogue → a marketplace listing owned by them shows the real realtor + profile link → a moderator
  verifies → the badge appears on the profile + the listing.

## 11. Risks

- **Marketplace serialization** — the `AgentSchema` additions must be always-populated (default `false`/`null`)
  or existing listing tests/consumers break; verify the listing unit/e2e/web suites early. Highest-risk item.
- **Slug collisions with routes** — the reserved denylist must cover every top-level web route (`search`, `new`,
  `obj`, `p`, `r`, `favorites`, `contact`, `offer`, `api`, `agent`, `my`, `requests`, `valuation`, …) or a slug
  could shadow a real page.
- **Public page vs subscription** — the page stays up on a lapsed subscription (decision); editing is gated.
- **Logo pipeline** — reuse `processImage`; a single logo per profile, replaced on reupload.
- **`/r/:slug` serving via `NotFoundShellFilter`** — like `/p/:token`, gate strictly on the single-segment
  pattern so no other non-`/api` path regresses, and never touch `/api/r/:slug`.
