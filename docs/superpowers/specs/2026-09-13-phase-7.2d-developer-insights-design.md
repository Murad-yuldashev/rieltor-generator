# Phase 7.2d — Developer AI finance insights (narrative over the finance snapshot) (design)

**Status:** approved design, ready for planning
**Branch:** `claude/phase-7.2d-developer-insights` (off master `4c6b0af`, the Phase 7.2c merge)
**Roadmap:** Phase 7 (Growth layer, last roadmap phase) — 7.1 mortgage → **7.2 AI assistant** → 7.3 map → 7.4 journal. Phase 7.2 slices: 7.2a buyer AI search (done) → 7.2b realtor lead assistant (done) → 7.2c realtor AI content (done) → **7.2d developer AI insights** (the last 7.2 slice).

---

## 1. Goal

Give a developer organization one-tap **AI narrative insight** over its own finance snapshot: from the
already-computed 6.4b aggregates (contracted / collected / outstanding / overdue totals, net commission,
org balance, and the overdue debtors) produce a short, plain-Uzbek advisory paragraph — what the numbers
say plus one practical recommendation — shown under the "Moliya" dashboard cards.

The **numbers are server-authoritative** (they come from `FinanceService`, the same source the cards
render); Gemini only _narrates_ them, which keeps hallucination risk low. Like the valuation, the 7.2b
lead assistant, and the 7.2c content generator, it is a **hybrid**: a template narration is always
computed from the aggregates, and Gemini enriches it when a key is available. It reuses the existing
`GeminiService` and the existing `FinanceService`.

This is the fourth and final slice of the Phase 7.2 AI-assistant subsystem; it follows the reuse pattern
the prior slices established (a `GeminiService` call with strict server-side handling of the model output,
never trusting it) and the hybrid always-a-usable-result fallback.

## 2. Scope

**In scope (7.2d):**

- A developer-gated **`GET /api/crm/finance/insight`** (org-scoped): loads this org's `FinanceService`
  summary + debtors and returns `{ ai, insight }` — a Gemini-authored narrative when available, a
  structured template narration otherwise.
- A shared DTO for the response (no request DTO — the server derives everything from the caller's org).
- An **"AI tahlil"** affordance on the developer's **Moliya** page in `apps/crm` that calls the endpoint
  and shows the narrative in a **copyable** panel under the summary cards.

**Deferred (named, not built):**

- A multi-turn / question-answer **finance chatbot** (7.2d is one-shot: a single narrative over the
  current snapshot, no follow-up dialog).
- **Charts / graphs / trend visualizations**, and any **forecasting / prediction** (7.2d narrates the
  _current_ aggregates only — no time series, no projection).
- **Platform-wide (moderator) analytics** — 7.2d is strictly the caller's own org.
- **Storing** the generated insight, an insight **history**, scheduled/emailed digests, PDF/export.
- Tone / language selection.
- The rest of Phase 7 (7.3 map, 7.4 journal) and everything already listed as deferred.

## 3. Design decisions (resolved)

1. **Output = a single narrative paragraph** (`{ ai, insight }`), shown as advisory text under the
   existing Moliya cards. The exact figures stay on the cards; the insight interprets them.
2. **Numbers server-authoritative; AI only narrates.** The endpoint loads the aggregates from
   `FinanceService` (the same numbers the cards show) and passes them to Gemini with an explicit
   "use only these numbers, invent nothing" instruction — so the model narrates, it does not compute.
   This is the core hallucination guard for a finance feature.
3. **Hybrid, always-usable (like 7.2b / 7.2c / valuation).** A pure template narration is always computed
   from the aggregates; no API key / an unusable model response → the template (never a 503). Gemini is an
   enrichment, not a dependency.
4. **Developer-gated, org-scoped.** The route is added to the existing `FinanceController`
   (`@Controller('crm')`, `@UseGuards(JwtGuard, DeveloperGuard)`), and resolves the org exactly as its
   siblings do — `await this.developer.orgIdOf(u.id)`. A caller only ever sees its own org's finances; no
   cross-org read is possible.
5. **`GET`, no body, on-demand.** Mirrors `GET /api/crm/finance` and `GET /api/crm/debtors` — the server
   derives all inputs from the org, so there is nothing to send. The client fetches it only when the user
   presses the button (it is not auto-loaded with the page), so each Gemini call is user-initiated.
6. **PII minimized to the external model.** The prompt includes the aggregate figures plus, at most, the
   **top debtor's name + overdue amount** (a debtor name already appears on the same page, and the 7.2b
   assistant already sends client names to Gemini) — but **never a buyer phone number**, which adds
   nothing to a narrative. (Open to tightening to name-free during review.)
7. **Draft-only, stateless, additive.** Nothing stored, no data-model change; a route + helpers added to
   the existing controller/module; the finance summary + debtors endpoints untouched.

## 4. Data model

**No change.** 7.2d is a stateless read over the existing finance aggregates; nothing is written or added.

## 5. Backend

### 5.1 Shared DTO (`packages/shared/src/schemas.ts`)

Only a response — there is no request body (the server derives the org from the JWT).

```ts
/** The developer AI finance-insight result. ai=true → Gemini-authored; ai=false → template narration. */
export const FinanceInsightResponseSchema = z.object({
  ai: z.boolean(),
  insight: z.string(), // a short Uzbek narrative over the org's finance snapshot
});
```

Plus the inferred type `FinanceInsightResponse`.

### 5.2 The insight route (`apps/api/src/developer/finance.controller.ts`)

Add a third handler to the existing `FinanceController` (it already injects `FinanceService` +
`DeveloperService` and carries `JwtGuard + DeveloperGuard`); inject `GeminiService` as well.

```ts
@Get('finance/insight')
async insight(@CurrentUser() u: { id: string }): Promise<FinanceInsightResponse> {
  const orgId = await this.developer.orgIdOf(u.id);
  const [summary, debtors] = await Promise.all([
    this.finance.summary(orgId),
    this.finance.debtors(orgId),
  ]);
  const template = buildInsightTemplate(summary, debtors);
  const raw = await this.gemini.generate(buildInsightPrompt(summary, debtors), { maxTokens: 300 });
  return parseInsight(raw, template);
}
```

- Route `/api/crm/finance/insight` — distinct from `@Get('finance')` (exact-path match), no collision.
- Never throws for an AI/parse problem: `gemini.generate` returns `null` on no-key/error, and
  `parseInsight` falls back to the template.

**Module wiring:** `DeveloperModule` adds `AiModule` to its `imports` (for `GeminiService`, which
`AiModule` exports). **No cycle** — `AiModule`'s transitive closure is
`{AuthModule, AgentModule → PresentationsModule}`, none of which imports `DeveloperModule` (verified);
`FinanceService`/`DeveloperService` are already `DeveloperModule` providers.

### 5.3 The template (`apps/api/src/developer/finance-insight.template.ts`) — pure, always computable

`buildInsightTemplate(summary: FinanceSummary, debtors: DebtorRow[]): string`:

- A short Uzbek narration built from the aggregates, e.g. a contracted/collected line
  (with a **collection percentage**), an outstanding/overdue line, a net-commission + balance line, and
  a debtor line naming the **top debtor** (`debtors[0]`, already sorted most-overdue-first) — or a
  "Qarzdor yo'q" clause when the list is empty.
- **Money** via the shared **`formatPriceSom(som, 'SALE')`** (its `groupDigits` is the ICU-free string
  regex — BigInt-safe, and it renders numbers **identically to the Moliya cards** — no `toLocaleString`).
- **Collection %** is **BigInt-safe**: `contractedSom === '0'` → guarded (no divide-by-zero, e.g. "0%" or
  the clause omitted); otherwise computed with BigInt so a value above `2^53` never loses precision
  (`Number((collected * 100n) / contracted)`), then rendered as an integer percent.
- Every interpolated field null-guarded; the debtor clause guarded on `debtors.length` (empty → no
  `debtors[0]` access). `orgBalanceSom` may be negative (a debt) — its sign is read off the string, and a
  negative balance narrates as a debt, never `Number()`-ed.
- A closing recommendation clause is derived from the figures (e.g. overdue/debtors present → a
  follow-up-on-collections nudge; otherwise a steady-state line). Pure string logic, no I/O.

### 5.4 The prompt + output handling (`apps/api/src/developer/finance-insight.parse.ts`) — untrusted output

- `buildInsightPrompt(summary, debtors)`: an Uzbek instruction — role ("quruvchi tashkilot uchun
  moliyaviy tahlilchi yordamchi"), the aggregate figures as **the authoritative numbers**, at most the
  top debtor's **name + overdue amount** (§3.6 — **no phone**), and: "faqat shu raqamlardan foydalan,
  yangi raqam o'ylab topma; 2-4 gaplik qisqa o'zbekcha tahlil yoz + bitta amaliy tavsiya; oddiy matn
  qaytar (JSON emas)."
- `parseInsight(raw: string | null, template: string): FinanceInsightResponse` — pure, **never trusts the
  model** and **never throws**. The model returns a plain narrative (not JSON), so no `JSON.parse` is
  needed; the discipline is: `raw == null` → `{ ai: false, insight: template }`; strip any code fences
  and trim; empty after trimming → the template; otherwise **length-cap** (slice to a sane max, e.g.
  ~1200 chars, so a runaway response can't bloat the payload) → `{ ai: true, insight: cleaned }`.
  Node-checkable in isolation, exactly like the 7.2a/b/c parsers.

## 6. Frontend (`apps/crm`, FSD)

- **`features/finance-insight/`** — a new feature (fully self-contained — it needs no finance data from
  the client; the server loads everything):
  - `model/use-finance-insight.ts` — `useFinanceInsight()` (a mutation that calls
    `apiGet('/api/crm/finance/insight', FinanceInsightResponseSchema)`; on a network/HTTP error it
    resolves to a minimal client fallback `{ ai: false, insight: <graceful Uzbek line> }` so a failure
    never breaks the panel — the 7.2c `use-listing-content` pattern).
  - `ui/finance-insight.tsx` — an **"AI tahlil"** button; on click it fetches, then shows the narrative in
    a **read-only** box (with an **`aria-label`** — the 7.1/7.2b a11y lesson, WCAG 4.1.2) plus a
    **"Nusxa olish"** copy button (`navigator.clipboard.writeText`, guarded — the presentations / 7.2b/c
    pattern) and a small **"AI" / "namuna"** tag from `ai`. Uzbek copy.
- **Wire into the Moliya page** (`apps/crm/src/pages/finance/ui/finance-page.tsx`): render
  `<FinanceInsight />` after `<FinanceCards>` (advisory under the numbers, before the debtor table). The
  page composes; the feature imports only `@rieltor/shared` + the crm `@/shared/*` client/UI — it does
  **not** import `@/features/finance` (FSD: a feature imports only entities/shared; the page composes).
- **FSD:** `finance-insight` imports only `@rieltor/shared` + `@/shared/*`. `yarn lint` (apps/crm's FSD
  boundary) must pass.

UI copy Uzbek; identifiers/routes/comments English.

## 7. Rulings & invariants (load-bearing)

- **R1 — never trust the model's output.** `parseInsight` never throws, treats `null`/empty as the
  template, strips fences, and length-caps the narrative before returning it; the client always receives a
  valid `{ ai, insight }` string, never a 500 and never an unbounded body.
- **R2 — hybrid, always usable.** The template narration is always computable from the aggregates; no
  key / outage / empty response → the template with `ai: false` (never a 503). Gemini only enriches.
- **R3 — developer-gated, org-scoped, numbers-authoritative.** `GET /api/crm/finance/insight` is guarded
  by `JwtGuard + DeveloperGuard` and reads **only** the caller's org (`orgIdOf(u.id)`, exactly like its
  siblings) — no cross-org read. The figures come from `FinanceService` (server-authoritative); the model
  narrates them under a "use only these numbers" instruction, so it cannot fabricate finance figures.
- **R4 — draft-only, stateless, additive.** No data-model change, no migration; a route + two helpers
  added, `DeveloperModule` gains an `AiModule` import for `GeminiService`; `FinanceService.summary` /
  `.debtors` and their endpoints are untouched.
- **R5 — type/style discipline (7.2a/b/c lessons).** Money via the shared `formatPriceSom` (ICU-free,
  matches the cards); the collection percentage is BigInt-safe and divide-by-zero-guarded; every
  interpolated field is null-guarded and the debtor clause is `length`-guarded; a negative `orgBalanceSom`
  is read as a string sign, never `Number()`-ed.
- **R6 — PII minimization.** The prompt sends aggregate figures + at most the top debtor's name + overdue
  amount — **never a buyer phone number** — to the external model.

## 8. Verification (no new test files — per project rule)

- `yarn typecheck` + `yarn lint` + `yarn build` green across api / shared / crm.
- Compiled-JS / pure-Node scratch (against a real `nest build`, never `tsx`, run from `apps/api` so
  `@rieltor/shared` resolves) of `parseInsight` + `buildInsightTemplate`:
  - (a) `parseInsight(null, tpl)` → `{ ai: false, insight: tpl }`;
  - (b) a whitespace-only / empty string → the template;
  - (c) a ```-fenced narrative → `ai: true` with the fences stripped and the text trimmed;
  - (d) an over-long string → `ai: true`, length-capped;
  - (e) `buildInsightTemplate` for: an org with overdue debtors, an org with **no** debtors, and an org
    with `contractedSom: '0'` (percentage guard) and a **negative** `orgBalanceSom` → a coherent Uzbek
    narrative with NO literal "undefined"/"NaN"/"Infinity", grouped money matching the cards, and a
    debtor clause present/absent as appropriate.
- Booted-Nest HTTP check (never tsx): `GET /api/crm/finance/insight` — no auth → 401; a logged-in
  NON-developer → 403 (DeveloperGuard); a developer (key unset) → 200 with `ai: false` and a non-empty
  `insight`.
- Browser smoke: in `apps/crm` Moliya, the "AI tahlil" button shows a narrative under the cards; "Nusxa
  olish" copies it.
- Full suite green before merge (shared 18, web 34, api 37, e2e 22 → 111), zero new test files.
