# Phase 3.2 — Client presentations + analytics + Telegram sharing design

_Date: 2026-08-27 · Branch: `claude/phase-3.2-presentations` · Base: master `1a46a7c` · Part of: Phase 3 (Product C) · Depends on: 3.1 (collections)_

## 1. Goal

Turn a realtor's **collection** (3.1) into a shareable, immutable **client presentation**:
a public tokenized link (`/p/:token`) showing the curated listings with the realtor's
**client-facing per-item notes**, tracked with per-listing **view analytics** (opens +
dwell time), and shared **Telegram-natively** via a `t.me/share` deep-link backed by a rich
`og:`-preview. This is Product C's **C3 (presentation) + C4 (analytics) + C5 (Telegram
sharing)** — the "ours alone" wedge.

## 2. Scope

1. **Snapshot** a collection → an immutable `Presentation` (+ items) at send time.
2. **Public `/p/:token` page** in `apps/web` (SSR shell + `og:` meta, like `/obj/:id`).
3. **Analytics** (C4): per-listing opens + dwell time, aggregated for the realtor.
4. **Telegram sharing** (C5): a `t.me/share/url` deep-link + the `og:`-preview.
5. **Per-item client-facing note editor** — the `CollectionItem.note` endpoint that 3.1
   reserved: `PATCH /api/agent/collections/:id/items/:listingId`. This note is the client-facing
   "why this fits you" comment shown in the presentation (**distinct from the private C9 notes**,
   which are never shared).
6. **Realtor cabinet** (`apps/agent`): create + share presentations, "Mening taqdimotlarim" list,
   per-presentation analytics.

### Non-goals

- No content-freeze of listing data — `PresentationItem` references the **live** listing
  (`listingId`); a removed listing renders "mavjud emas". The snapshot freezes the _curation_
  (which listings, order, notes), not the listing data.
- No bot-delivered sharing — the `t.me/share` deep-link only; bot delivery is a later enhancement.
- No **discoverable** public realtor profile / rating (that is 3.3). The presentation's
  "presented by <realtor>" header exposes only name + agency, **link-gated** to whoever has the
  presentation token — not a searchable profile.
- No editing a presentation after creation (immutable; "resend" = a fresh snapshot).
- No client accounts / client-side auth — the public token link is the access control.
- Real payment (Click/Payme), site generator (C1) — later.

## 3. Data model (Prisma)

```prisma
model Presentation {
  id                 String             @id @default(cuid())
  realtorId          String
  realtor            User               @relation(fields: [realtorId], references: [id], onDelete: Cascade)
  token              String             @unique                 // unguessable public URL id
  title              String
  clientLabel        String?
  sourceCollectionId String?                                    // reference only; not a FK dependency for reads
  createdAt          DateTime           @default(now())
  items              PresentationItem[]
  views              PresentationView[]
}

model PresentationItem {
  id             String       @id @default(cuid())
  presentationId String
  presentation   Presentation @relation(fields: [presentationId], references: [id], onDelete: Cascade)
  listingId      String
  listing        Listing      @relation(fields: [listingId], references: [id], onDelete: Cascade)
  position       Int
  note           String?                                        // client-facing comment (copied from CollectionItem.note)
}

model PresentationView {
  id             String       @id @default(cuid())
  presentationId String
  presentation   Presentation @relation(fields: [presentationId], references: [id], onDelete: Cascade)
  listingId      String?                                        // null = the presentation itself was opened
  durationMs     Int?                                           // dwell for a per-listing view
  at             DateTime     @default(now())
  @@index([presentationId])
}
```

Back-relations: `User { presentations Presentation[] }`; `Listing { presentationItems PresentationItem[] }`.
The `token` is a second cuid (unguessable). `sourceCollectionId` is a soft reference (a plain
string, no FK) so deleting the source collection never affects a sent presentation.

## 4. Snapshot flow

`POST /api/agent/collections/:id/present` (RealtorGuard, ownership-scoped):

1. Load the collection (owned) + its items (ordered).
2. Create a `Presentation { realtorId, token: <cuid>, title: <collection.name>, clientLabel?, sourceCollectionId: id }`.
3. Copy each `CollectionItem` → `PresentationItem { listingId, position, note }` in one `$transaction`.
4. Return `{ id, token, url: `${PUBLIC_BASE_URL}/p/${token}` }`.
   An empty collection is rejected (`BadRequestException` "Kolleksiya bo'sh").

## 5. Public presentation page + analytics loop

**Page (`apps/web`, `/p/:token`)** — mirrors the `/obj/:id` SSR pattern:

- `SsrController` gains `@Get('p/:token')`: fetch the presentation for `og:` meta (title,
  first item's image, "N obyekt · <realtor>") and return the SPA shell with meta injected; 404 →
  the shell with a 404 status. Add `p/:token` to the `setGlobalPrefix` exclude list next to
  `obj/:id` (it is NOT part of the static `SPA_ROUTES` list — it is a param route handled like
  `obj/:id`).
- The SPA (`apps/web`) gains a route `/p/:token` → `PresentationPage`: fetch `GET /api/p/:token`,
  render the title, the "<realtor> tayyorladi" header, and the ordered listing cards (live
  `ListingSummary` + the realtor's client-facing `note` shown prominently), each with a "Batafsil"
  link to `/obj/:id`. Cards render inline so dwell is measurable.

**Analytics loop (C4):**

- On load: `POST /api/p/:token/view {}` (presentation opened; `listingId` null).
- Per-listing: an `IntersectionObserver` accumulates each card's visible time; on
  `visibilitychange`(hidden)/`pagehide`, `navigator.sendBeacon` posts `{ listingId, durationMs }`
  for each card with dwell > a small threshold. Best-effort (background tabs etc. are approximate).
- The API appends `PresentationView` rows. Realtor aggregation: per listing → open count +
  avg/total dwell; presentation → total opens.

## 6. API

| Method + path                                       | Guard        | Purpose                                                                                                                                                                    |
| --------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/agent/collections/:id/present`           | RealtorGuard | Snapshot the owned collection → `{ id, token, url }`.                                                                                                                      |
| `GET /api/agent/presentations`                      | RealtorGuard | The realtor's presentations (title, clientLabel, createdAt, opens count, url).                                                                                             |
| `GET /api/agent/presentations/:id`                  | RealtorGuard | Detail + analytics (per-item: opens + avg dwell; total opens). Ownership-scoped.                                                                                           |
| `DELETE /api/agent/presentations/:id`               | RealtorGuard | Delete a presentation (revokes the public link).                                                                                                                           |
| `PATCH /api/agent/collections/:id/items/:listingId` | RealtorGuard | Set the client-facing `CollectionItem.note` (the 3.1-reserved endpoint).                                                                                                   |
| **`GET /api/p/:token`**                             | **public**   | Presentation for the public page: title, realtor display (name, agency), ordered items (live `ListingSummary` + `note`). 404 on unknown token. **Not subscription-gated.** |
| **`POST /api/p/:token/view`**                       | **public**   | Ingest an analytics event `{ listingId?, durationMs? }`. Lightweight; token-scoped. **Not subscription-gated.**                                                            |

**Guarding:** creation/list/detail/delete + the item-note edit are `RealtorGuard` (role + active
subscription, ownership-scoped). The two public endpoints are **unauthenticated and NOT
subscription-gated** — a lapsed realtor's already-sent links must keep working for the client.
The `token` (unguessable cuid) is the access control.

## 7. Realtor cabinet (`apps/agent`)

- **Collection detail** (3.1): a per-item **note editor** (textarea) → `PATCH .../items/:listingId`
  (the client-facing comment); and a **"Taqdimot yaratish va ulashish"** button → `present` →
  shows the public URL + "Nusxa olish" (copy) + **"Telegramда ulashish"**
  (`https://t.me/share/url?url=<url>&text=<caption>`, C5).
- **"Mening taqdimotlarim"** (new nav item, gated): a list of presentations (title, clientLabel,
  created, opens) → detail with the link + share actions + **analytics** (per-listing "N marta
  ochildi · o'rtacha X soniya", total opens, most-viewed) + delete.

## 8. Modules & wiring

- `apps/api/src/presentations/` — a new module: `presentations.service.ts` (snapshot, list, detail
  - analytics aggregation, delete), a controller split into the RealtorGuard-protected
    `/api/agent/presentations*` + `collections/:id/present` routes and the **public**
    `/api/p/:token` + `/api/p/:token/view` routes. The item-note `PATCH` extends the existing
    `CollectionsService`/agent controller (Task in 3.2).
- `apps/web` — the `SsrController` `p/:token` handler + `bootstrap.ts` exclude entry + the SPA
  `/p/:token` route/page + analytics client.
- `apps/agent` — a `presentations` feature + the collection-detail note editor + the "Mening
  taqdimotlarim" pages.
- Shared Zod DTOs in `@rieltor/shared`.

## 9. Constraints

- Uzbek user-facing copy; **English** identifiers/comments ([[english-code-only]]).
- **No new test files** ([[no-tests-unless-asked]]); the existing **111**-suite stays green; verify
  with `yarn lint` / `yarn typecheck` / `yarn build` (all four workspaces) + browser smoke.
- **No new env var** — `PUBLIC_BASE_URL` (already validated) builds the public URL; analytics
  needs no external service.
- The public `/p/:token` + `/api/p/:token*` are unauthenticated, token-gated, and **not**
  subscription-gated (sent links keep working). Creation/analytics-read are RealtorGuard-scoped to
  the owning realtor.
- The **client-facing** item note (`CollectionItem.note` → `PresentationItem.note`) is distinct
  from the **private** C9 `Note` — the presentation never exposes C9 notes.
- FSD / Nest boundaries respected; `apps/agent` never imports `apps/web`. The public page reuses
  the marketplace's listing rendering; migration is additive.

## 11. Risks

- **Public write endpoint abuse** — anyone with the token can post view events; mitigated by
  token-scoping (only that presentation's stats), a lightweight write, and no PII. A realtor's own
  preview views may slightly inflate stats (acceptable for v1).
- **Dwell accuracy** — `IntersectionObserver` + `sendBeacon` is best-effort (background tabs,
  early unloads); treated as an approximation, not billing-grade.
- **Live-listing reference** — a deleted/unpublished listing renders "mavjud emas" in a sent
  presentation; the realtor resends. Acceptable.
- **Semi-public realtor identity** — the presentation reveals the realtor's name + agency to anyone
  with the link (by design); it is link-gated, not discoverable (full public profile is 3.3).
