# Phase 7.4 — Journal / blog with SEO landing pages (design)

**Status:** approved design, ready for planning
**Branch:** `claude/phase-7.4-journal` (off master `52873ba`, the Phase 7.3 merge)
**Roadmap:** Phase 7 (Growth layer, last roadmap phase) — 7.1 mortgage ✓ → 7.2 AI assistant ✓ → 7.3 map ✓ → **7.4 journal** (A16, the final roadmap slice).

---

## 1. Goal

An editorial **journal / blog**: platform moderators author articles in Markdown, and published articles
get public **SEO landing pages** — a `/jurnal` list and a `/jurnal/:slug` article page — with
server-injected meta tags (title / description / OG image) via the platform's established SSR-meta seam,
so articles share and rank well. This is A16 ("Journal / blog with SEO landing pages"), the last roadmap
item.

## 2. Scope

**In scope (7.4):**

- **Data:** an additive `Article` model (slug, title, excerpt, Markdown body, optional cover image,
  category, DRAFT/PUBLISHED status, publishedAt, moderator author) + an `ArticleCategory` enum.
- **Public** (`apps/web`, no auth): `GET /api/jurnal` (published list, optional category filter) +
  `GET /api/jurnal/:slug` (a published article); a `/jurnal` list page and a `/jurnal/:slug` article page
  that renders the Markdown body **safely** (react-markdown, code-split); a header "Jurnal" nav link.
- **SEO:** server-injected meta for `/jurnal/:slug` (and the `/jurnal` list shell) via the existing
  SSR-meta seam — a `buildArticleMetaTags` mirroring `buildComplexMetaTags`, wired the same way `/jk/:slug`
  is (the `NotFoundShellFilter` slug-page path), plus `/jurnal` added to `SPA_ROUTES` + the prefix-exclude.
- **Moderation** (`apps/web`, RolesGuard MODERATOR/ADMIN): a `moderation/journal` API + a
  `moderation-journal` page — list all articles (incl. drafts), create/edit (Markdown textarea),
  publish / unpublish, upload a cover image (reusing the existing image-upload seam).

**Deferred (named, not built):**

- Multi-language articles (A17), comments, like/share counters, a tag system (only a fixed `category`),
  article full-text search, RSS, scheduled publishing, AI-assisted writing, reactions.
- Reels (A15), referral/loyalty (A19), promoted articles.
- Rich WYSIWYG editing (the moderator writes Markdown in a textarea); article revisions/history.
- Rendering the article body server-side (the app is a client SPA — the body renders client-side; only
  the SEO meta is server-injected, exactly as listings/complexes do).

## 3. Design decisions (resolved)

1. **Moderator-authored editorial CRUD.** Articles are platform content: a `moderation/journal` API
   guarded by `JwtGuard + RolesGuard` `@Roles('MODERATOR','ADMIN')` (the `moderation/developers` pattern).
   Buyers only ever read PUBLISHED articles; drafts are never public.
2. **Markdown body, rendered safely.** The moderator writes Markdown in a textarea; the public article
   page renders it with **react-markdown** — Markdown → React elements, **no `rehype-raw`, no
   `dangerouslySetInnerHTML`**, react-markdown's default URL sanitization (strips `javascript:`) — so
   there is **no XSS** by construction (the 7.3 lesson). Body images (`![]()`) are allowed
   (moderator-authored, http(s)). The renderer is **code-split** (React.lazy on the article route — the
   7.3 bundle lesson), since react-markdown + remark pulls ~40-60 KB.
3. **SEO via the established SSR-meta seam.** `/jurnal/:slug` gets server-injected meta
   (`buildArticleMetaTags`: title, excerpt → description, coverImage → og:image) exactly as `/jk/:slug`
   does through `NotFoundShellFilter` + `buildComplexMetaTags`. `/jurnal` (the list) is added to
   `SPA_ROUTES` (served as the shell, prefix-excluded). The body is client-rendered; the meta is what
   search/social consume — consistent with every other public page.
4. **Fixed category enum** (`ArticleCategory`: `BOZOR` [market], `QOLLANMA` [guide], `YANGILIK` [news]),
   with `Record<ArticleCategory,string>` label maps (finite keys, no `noUncheckedIndexedAccess` gap — the
   7.2a lesson). Drives the list filter + card badge. No free tags.
5. **Cover image via the existing upload seam.** An optional cover `Image` uploaded through the same
   `processImage` + `FileInterceptor` pattern complex images use; drives the list card + the `og:image`.
6. **Slug from the title.** Generated by slugifying the title — lowercased, non-alphanumeric → hyphens,
   apostrophes/non-ASCII stripped (the 7.2c hashtag lesson) — with a uniqueness guard; editable while a
   draft, stable once published.

## 4. Data model

Additive migration `phase_7_4_journal`:

- New enum `ArticleCategory { BOZOR, QOLLANMA, YANGILIK }`.
- New enum `ArticleStatus { DRAFT, PUBLISHED }`.
- New model **`Article`**: `id`, `slug` (`@unique`), `title`, `excerpt`, `body` (Markdown text),
  `category` (`ArticleCategory`), `status` (`ArticleStatus @default(DRAFT)`), `publishedAt` (`DateTime?`),
  `coverImageId`? + `coverImage` (relation to the existing `Image`, or a dedicated `ArticleImage` if the
  `Image` model is listing-bound — a plan detail), `authorId` + `author` (`User`, the moderator),
  `createdAt`, `updatedAt`, `@@index([status, publishedAt])`.

No existing table is modified beyond the additive relation.

## 5. Backend

### 5.1 Shared DTOs (`packages/shared/src/schemas.ts`)

- `ArticleCategorySchema` (`z.enum(['BOZOR','QOLLANMA','YANGILIK'])`); `ArticleStatusSchema`.
- `ArticleSummarySchema` — list card: `slug`, `title`, `excerpt`, `category`, `coverImage` (nullable),
  `publishedAt`.
- `ArticleDetailSchema` — `ArticleSummarySchema` + `body`, `authorName`.
- `ArticleCreateSchema` / `ArticleUpdateSchema` — `title`, `excerpt`, `body`, `category` (bounded lengths);
  status/slug are server-managed.
- `ModeratorArticleRowSchema` — the moderation list row (adds `status`, `id`).

### 5.2 Public journal (`apps/api/src/journal-public/`)

- **`GET /api/jurnal`** (no guard, `/jk` pattern): PUBLISHED articles, newest first, optional
  `?category=` filter → `ArticleSummary[]`.
- **`GET /api/jurnal/:slug`** (no guard): the PUBLISHED article by slug → `ArticleDetail`; unknown/draft
  slug → 404.
- A mapper (Article row → DTO); the module reads only `PrismaService`.

### 5.3 Moderation journal (`apps/api/src/moderation-journal/` — RolesGuard)

- `@Controller('moderation/journal')` + `@UseGuards(JwtGuard, RolesGuard)` + `@Roles('MODERATOR','ADMIN')`:
  - `GET` → all articles (incl. drafts) as `ModeratorArticleRow[]`.
  - `GET /:id` → the full article for editing.
  - `POST` → create a draft (slug generated from title, uniqueness-guarded; `authorId` = the caller).
  - `PATCH /:id` → edit (title/excerpt/body/category; regenerate slug from title only while DRAFT).
  - `POST /:id/publish` / `POST /:id/unpublish` → flip status (publish sets `publishedAt`; idempotent
    guards like the other moderation flips).
  - `POST /:id/cover` → upload/replace the cover image (`FileInterceptor` + `processImage`, reusing the
    complex-image seam).

### 5.4 SSR meta (`apps/api/src/ssr/`)

- Add `buildArticleMetaTags(article, slug, baseUrl)` to `meta.ts` (mirrors `buildComplexMetaTags`:
  title, excerpt → description, coverImage → absolute og:image, `${baseUrl}/jurnal/${slug}`).
- Wire `/jurnal/:slug` into the same slug-page path `/jk/:slug` uses (a `NotFoundShellFilter` branch that
  loads the published article and injects the meta); add `'jurnal'` to `SPA_ROUTES` (list shell +
  prefix-exclude). `journal-public` is imported where the SSR seam needs it.

## 6. Frontend (`apps/web`, FSD)

- **Public list** (`pages/jurnal`): `GET /api/jurnal` cards (cover, category badge, title, excerpt, date)
  - a category filter; links to `/jurnal/:slug`.
- **Public article** (`pages/jurnal-article`, route `/jurnal/:slug`): cover + title + category + date +
  the **react-markdown** body (a `shared/ui` markdown component, **code-split** via `React.lazy`); a
  graceful 404 for an unknown slug.
- **Header nav**: a "Jurnal" link (and the home footer "Journal" link the mockup lists).
- **Moderation** (`pages/moderation-journal`, RolesGuard-gated route like the other moderation pages): a
  list of all articles (status badge) + a create/edit form (title, excerpt, category select, Markdown
  **textarea** with a small live preview reusing the same markdown component, cover upload) + publish /
  unpublish controls.
- **FSD:** a `journal` entity (API queries + card); the markdown renderer in `shared/ui`; pages compose.
  UI copy Uzbek; identifiers/routes/comments English.

## 7. Rulings & invariants (load-bearing)

- **R1 — Markdown rendered safely (no XSS).** react-markdown with NO `rehype-raw` and NO
  `dangerouslySetInnerHTML`; default URL sanitization on; the body is never injected as raw HTML. (The
  7.3 XSS lesson, applied to a much larger free-text surface.)
- **R2 — moderator-gated CRUD; public read-only PUBLISHED.** All writes require
  `JwtGuard + RolesGuard @Roles('MODERATOR','ADMIN')`; the public endpoints return only PUBLISHED
  articles; a draft/unknown slug 404s (never leaks a draft).
- **R3 — additive.** One additive migration (new enums + `Article` + the cover relation); no existing
  table altered; no new required env.
- **R4 — SEO via the established seam.** `buildArticleMetaTags` + the `/jk/:slug`-style wiring; `/jurnal`
  in `SPA_ROUTES` + prefix-exclude. No bespoke SSR machinery.
- **R5 — slug discipline.** Slug slugified from the title (lowercase, non-alphanumeric → hyphens,
  apostrophes/non-ASCII stripped — the 7.2c lesson), uniqueness-guarded, stable once published.
- **R6 — code-split the renderer.** react-markdown loads via `React.lazy` on the article + the moderation
  preview, so it stays out of the initial bundle (the 7.3 bundle lesson).
- **R7 — type/style discipline.** `Record<ArticleCategory,string>` label maps (no
  `noUncheckedIndexedAccess` gap); dates/enums null-guarded; cover optional everywhere.
