# Phase 6.2 — Contracts (design)

**Status:** approved design, ready for planning
**Branch:** `claude/phase-6.2-contracts` (off master `e6551f0`, the Phase 6.1 merge)
**Depends on:** 5.2 (Booking convert→SOLD), 5.4 (Fixation + cross-CRM commission), 6.1 (org wallet + funded commission)
**Roadmap:** Phase 6 decomposition — 6.1 org wallet → **6.2 Contracts** → 6.3 clawback/reconciliation → 6.4 payment schedules + debtors + finance/KPI (project-overview §4r).

---

## 1. Goal

Introduce the **Contract** — the durable, auto-numbered legal record of a closed sale that
binds a **buyer** and a **developer org** for a **unit**. Today the only trace of a closed
deal is a `CONVERTED` Booking + a `SOLD` Unit + (on the lead path) a `CONVERTED` Fixation;
there is no contract entity. 6.2 creates a Contract **at the moment the deal closes**
(Booking `convert`→SOLD), inside the same atomic transaction, so every future sub-phase
(6.3 clawback, 6.4 payment schedules) has a stable record to hang off.

Spec authority — the only field-level requirement in the product spec is §4.1 Sales core:

> "Contracts — templates, variations, multi-currency, auto-numbering, online signing with national ID (JSHSHIR) verification."

§6.3 names `Contract / PaymentSchedule / Payment / Invoice` as entities but gives **no fields**;
the Contract's shape is therefore a design decision, made below.

## 2. Scope

**In scope (6.2):**

- A `Contract` model + a per-org-per-year auto-numbering counter (`OrgContractCounter`).
- Contract **creation at convert**, inside the existing `count===1` atomic gate — one contract per converted booking.
- A **currency** field (default `SOM`) stored on the row — a cheap, forward-compatible placeholder for the spec's multi-currency (no FX conversion).
- A **signing stub**: a `signedAt` timestamp set by a developer action; real JSHSHIR verification is deferred.
- A CRM **Contracts list + detail** page (developer cabinet) + a nav tab.

**Deferred (named, not built):**

- `PaymentSchedule` / `Payment` / `Invoice` + debtor register + finance-KPI → **6.4**.
- Commission clawback / reconciliation → **6.3**.
- **Real** online signing + JSHSHIR / national-ID verification (partner-dependent) — 6.2 stubs a `signedAt` only.
- Multi-currency **FX conversion** (a non-SOM price has no source today; `Unit.priceSom` is SOM).
- Contract **templates / variations engine** (the §4.1 "templates, variations" clause).
- **Backfill** of contracts for pre-6.2 converted bookings — contracts exist only for converts after 6.2 ships.
- Realtor-side (apps/agent) contract view — the realtor already sees fixation status/commission.

## 3. Design decisions (the four forks, resolved)

1. **Creation model — create AT convert (wraps the sale).** The convert `$transaction`'s
   `count===1` gate is the one atomic deal-close moment; a Contract slotted inside it inherits
   at-most-once creation for free, with all data (price, org, buyer, fixation) already in hand.
   Gating convert on a pre-signed contract would invert the flow (a draft at book, a status
   machine, changes to `book()` + the shaxmatka UI) — not chosen. Signing is a later stub
   transition on the already-created row.

2. **Buyer identity — nullable `buyerId` User? + denormalized snapshot.** A hard buyer `User`
   exists **only** on the fixation path (`Fixation → PropertyRequest → author`). A walk-in
   booking has only free-text `clientName/clientPhone`. So `Contract.buyerId` is `User?`
   (populated only via the lead author), and `buyerName` / `buyerPhone` are always snapshotted
   on the row (surviving later edits or a deleted lead). No shadow-User upsert.

3. **Auto-numbering — per-org, per-year sequential, e.g. `2026-0001`.** No sequence primitive
   exists (all ids are `cuid()`). A dedicated `OrgContractCounter` keyed on `([orgId, year])`
   is incremented atomically inside the convert tx; the number is `${year}-${padded seq}`.
   `Contract.@@unique([orgId, number])` is the backstop.

4. **Currency + signing — both in, minimally.** A `currency` enum (default `SOM`) is stored now
   (cheap, multi-currency-ready, no FX). Signing is a `signedAt DateTime?` stub set by
   `POST /api/crm/contracts/:id/sign`; real JSHSHIR is deferred.

## 4. Data model (additive migration)

All changes are additive: two new enums, two new tables, and virtual back-relations on existing
models (no column added to any existing table — every FK lives on the new `Contract` row).

```prisma
/// Contract settlement currency (6.2). SOM-only today; extend via ALTER TYPE ADD VALUE
/// when real multi-currency + FX lands. No conversion is performed in 6.2.
enum Currency {
  SOM
}

/// Contract lifecycle (6.2). Created ACTIVE at the deal-close; CANCELLED is reserved
/// for the 6.3 clawback/unwind path (not written in 6.2).
enum ContractStatus {
  ACTIVE
  CANCELLED
}

/// The durable sale record, created at Booking convert→SOLD. One per converted booking
/// (bookingId @unique = the idempotency backstop). Money is BigInt, string end-to-end.
model Contract {
  id           String         @id @default(cuid())
  /// Human-facing, per-org-per-year sequential, e.g. "2026-0001". Unique within an org.
  number       String
  orgId        String
  org          Organization   @relation(fields: [orgId], references: [id], onDelete: Cascade)
  unitId       String
  unit         Unit           @relation(fields: [unitId], references: [id], onDelete: Cascade)
  /// The converted booking this contract wraps — 1:1; the at-most-once backstop.
  bookingId    String         @unique
  booking      Booking        @relation(fields: [bookingId], references: [id], onDelete: Cascade)
  /// The cross-CRM fixation credited for the sale, when the buyer came via a realtor lead.
  fixationId   String?
  fixation     Fixation?      @relation(fields: [fixationId], references: [id], onDelete: SetNull)
  /// The platform buyer User — populated ONLY on the fixation path (the lead author);
  /// null for a walk-in booking, which carries only the snapshot name/phone below.
  buyerId      String?
  buyer        User?          @relation("BuyerContracts", fields: [buyerId], references: [id], onDelete: SetNull)
  /// Buyer identity SNAPSHOT at convert (survives later profile edits / a deleted lead).
  buyerName    String
  buyerPhone   String
  /// Agreed price SNAPSHOT of unit.priceSom at convert; null-tolerant (a null-price unit
  /// still converts). BigInt, serialized as string.
  agreedAmount BigInt?
  currency     Currency       @default(SOM)
  status       ContractStatus @default(ACTIVE)
  /// Stub online-signing (6.2): a developer action stamps this. Real JSHSHIR is deferred.
  signedAt     DateTime?
  createdAt    DateTime       @default(now())

  @@unique([orgId, number])
  @@index([orgId, createdAt])
}

/// Per-org-per-year monotonic counter backing Contract.number. Composite PK (no cuid) so a
/// native upsert/ON CONFLICT increment is atomic and race-safe across concurrent converts.
model OrgContractCounter {
  orgId   String
  year    Int
  lastSeq Int    @default(0)

  @@id([orgId, year])
}
```

Back-relations to add (virtual — no table columns):

- `Organization`: `contracts Contract[]`
- `Unit`: `contracts Contract[]`
- `Booking`: `contract Contract?` (1:1)
- `Fixation`: `contracts Contract[]`
- `User`: `buyerContracts Contract[] @relation("BuyerContracts")`

`OrgContractCounter.orgId` is a plain scalar column (no FK / back-relation) — it is a bare counter.

Migration name: `phase_6_2_contracts`. `CREATE TYPE "Currency"`, `CREATE TYPE "ContractStatus"`,
`CREATE TABLE "Contract"` (+ its unique/index/FKs), `CREATE TABLE "OrgContractCounter"`. No `ALTER`
of any existing table. No data write.

## 5. Backend

### 5.1 Shared DTOs (`packages/shared/src/schemas.ts`)

```ts
export const CurrencySchema = z.enum(['SOM']);
export const ContractStatusSchema = z.enum(['ACTIVE', 'CANCELLED']);

/** A durable sale contract (6.2). `agreedAmount` is BigInt-as-string, null when the unit had
 *  no price at convert. `buyerId` is null for a walk-in sale (no platform user). */
export const ContractSchema = z.object({
  id: z.string(),
  number: z.string(),
  unitId: z.string(),
  fixationId: z.string().nullable(),
  buyerId: z.string().nullable(),
  buyerName: z.string(),
  buyerPhone: z.string(),
  agreedAmount: z.string().regex(/^\d+$/).nullable(),
  currency: CurrencySchema,
  status: ContractStatusSchema,
  signedAt: z.string().nullable(),
  createdAt: z.string(),
});

/** A contract row for the org-wide CRM list — adds unit + building context. */
export const ContractRowSchema = ContractSchema.extend({
  unitNumber: z.string(),
  buildingName: z.string(),
});

export type Currency = z.infer<typeof CurrencySchema>;
export type ContractStatus = z.infer<typeof ContractStatusSchema>;
export type Contract = z.infer<typeof ContractSchema>;
export type ContractRow = z.infer<typeof ContractRowSchema>;
```

### 5.2 ContractService (`apps/api/src/developer/contract.service.ts`)

A new service, registered as a provider **in DeveloperModule** (not a separate module — it is
consumed by `BookingService`, which already lives there, so there is no import cycle and no
`forwardRef`). It mirrors the **caller-tx** idiom of `WalletService.credit` /
`OrgWalletService.debitForCommission`: `create` takes the caller's `Prisma.TransactionClient`
and never opens its own transaction.

```ts
/** Created inside the convert $transaction (count===1 gate). Assigns the per-org-per-year
 *  number atomically, then writes the contract. Never opens its own tx. */
async create(tx: Prisma.TransactionClient, input: {
  orgId: string; unitId: string; bookingId: string;
  fixationId: string | null; buyerId: string | null;
  buyerName: string; buyerPhone: string; agreedAmount: bigint | null;
}): Promise<void> {
  const year = new Date().getFullYear();
  // Native upsert compiles to INSERT ... ON CONFLICT DO UPDATE — atomic; concurrent converts
  // in the same (org, year) serialize on this row, so numbers never collide.
  const counter = await tx.orgContractCounter.upsert({
    where: { orgId_year: { orgId: input.orgId, year } },
    create: { orgId: input.orgId, year, lastSeq: 1 },
    update: { lastSeq: { increment: 1 } },
    select: { lastSeq: true },
  });
  const number = `${year}-${String(counter.lastSeq).padStart(4, '0')}`;
  await tx.contract.create({
    data: {
      number,
      orgId: input.orgId,
      unitId: input.unitId,
      bookingId: input.bookingId,
      fixationId: input.fixationId,
      buyerId: input.buyerId,
      buyerName: input.buyerName,
      buyerPhone: input.buyerPhone,
      agreedAmount: input.agreedAmount,
      // currency defaults SOM; status defaults ACTIVE.
    },
  });
}
```

Read/sign methods (own tx, org-scoped via `DeveloperService.orgIdOf`, foreign/missing → 404):

- `list(orgId): Promise<ContractRow[]>` — `contract.findMany({ where:{orgId}, orderBy:{createdAt:'desc'}, take:200, include:{unit:{select:{number, building:{select:{name}}}}} })`, mapped to `ContractRow` (`agreedAmount` → `String()` or null; `signedAt`/`createdAt` → ISO).
- `getOne(orgId, id): Promise<Contract>` — `findFirst({ where:{ id, orgId } })`; not found → `NotFoundException('Shartnoma topilmadi')`.
- `sign(orgId, id): Promise<Contract>` — load org-scoped (404 if foreign); a `CANCELLED` contract → `ConflictException`; if `signedAt` is null, stamp `signedAt = new Date()` (already-signed → return as-is, idempotent). Status stays `ACTIVE`.

### 5.3 ContractController (`apps/api/src/developer/contract.controller.ts`)

### 5.4 Convert wiring (`apps/api/src/developer/booking.service.ts`)

Three edits, all inside the existing convert path — the Contract is created for **every** convert
(fixation or walk-in), inside the `count===1` gate:

1. **`bookingOwnedOrThrow` select** — add `clientName: true` (currently only `clientPhone` is
   selected; the walk-in `buyerName` snapshot needs it).

2. **Fixation lookup** (the `findFirst` at ~line 136) — add
   `include: { propertyRequest: { select: { author: { select: { id: true, name: true, phone: true } } } } }`
   so the buyer `User` (the lead author) is reachable. `include` keeps all Fixation scalars, so
   the existing commission logic (`commissionBps`, `id`, `realtorId`) is unchanged.

3. **Contract creation** — inside `if (count === 1)`, **after** the commission `if (fixation) {…}`
   block (so it runs on every convert), inject `ContractService` and call:

```ts
const buyer = fixation?.propertyRequest?.author ?? null;
await this.contract.create(tx, {
  orgId: booking.unit.building.complex.orgId,
  unitId: booking.unitId,
  bookingId,
  fixationId: fixation?.id ?? null,
  buyerId: buyer?.id ?? null,
  buyerName: buyer?.name ?? booking.clientName, // User.name is nullable → fall back to the booking
  buyerPhone: buyer?.phone ?? booking.clientPhone, // author phone is canonical; walk-in uses the booking's
  agreedAmount: unit?.priceSom ?? null, // snapshot of the live SOLD price (null-tolerant)
});
```

`BookingService` constructor gains `private readonly contract: ContractService`.

## 7. Rulings & invariants (load-bearing)

- **R1 — every convert gets exactly one Contract.** The `create` call lives inside the `count===1`
  gate; because the ACTIVE→CONVERTED flip is atomic, `count===1` fires at most once per booking,
  so at most one Contract is created. `Contract.bookingId @unique` is the backstop against any
  future refactor.
- **R2 — number uniqueness under concurrency.** Two different bookings in the **same org+year**
  converting concurrently both increment `OrgContractCounter`; the native ON CONFLICT upsert
  serializes them on the counter row, so `lastSeq` values (and thus numbers) never collide.
  `@@unique([orgId, number])` makes any residual collision a loud failure, not a silent duplicate.
- **R3 — price is a snapshot, never an FK.** `agreedAmount` copies `unit.priceSom` at convert
  (the price is editable on a BOOKED unit right up to convert). A `null` price is tolerated —
  the sale still converts and the Contract records `agreedAmount = null` (never blocks convert).
- **R4 — buyer snapshot always; hard link only on the lead path.** `buyerName`/`buyerPhone` are
  always written (from the lead author when present, else the booking's free text); `buyerId` is
  non-null only when a matching ACTIVE fixation carries a lead author.
- **R5 — org-scoping.** Every contract read/sign is gated by `orgId = orgIdOf(caller)`; a foreign
  or missing id → 404. No cross-org read.
- **R6 — additive-only.** New enums + tables + virtual back-relations; no `ALTER`/`DROP` of any
  existing table; no data backfill.
- **R7 — money as string end-to-end.** `agreedAmount` serialized `String(bigint)` / `z.string().regex(/^\d+$/).nullable()`.
