# Phase 7.1 — Mortgage calculator + bank table (design)

**Status:** approved design, ready for planning
**Branch:** `claude/phase-7.1-mortgage` (off master `c74593d`, the Phase 6.4b merge — Phase 6 complete)
**Roadmap:** Phase 7 (Growth layer) — decomposed: **7.1 mortgage calculator + bank table** → 7.2 AI assistant → 7.3 map → 7.4 journal (+ deferred: showroom 3D, reels, telephony, omnichannel inbox, native mobile).

---

## 1. Goal

Give a buyer a mortgage (ipoteka) calculator: from a property price, down payment, interest rate, and
term, compute the estimated **monthly payment** + total paid + overpayment — prefilled from a bank
program the buyer picks, or a custom rate. A small **bank-program table** (seeded) feeds the rate/term
options. The calculator appears both as a widget on the listing detail (prefilled with that listing's
price) and as a standalone `/ipoteka` page.

The calculation is a client-side **estimate** (Number arithmetic — property prices fit safely inside
`Number`, and a mortgage schedule involves a floating interest rate anyway); it is explicitly not the
exact-BigInt money used for real transactions elsewhere. Real bank-rate feeds are partner-dependent
and deferred; 7.1 ships a curated seeded table.

## 2. Scope

**In scope (7.1):**

- A `MortgageProgram` table (seeded, read-only) + a public `GET /api/mortgage/programs`.
- A client-side annuity calculator (monthly / total / overpayment) with a program picker (prefill) +
  editable custom rate/term.
- A listing-detail mortgage widget (price prefilled) + a standalone `/ipoteka` page in `apps/web`.

**Deferred (named, not built):**

- Real bank-rate feed integration (partner-dependent); moderator CRUD for programs (7.1 is seed-only).
- Loan application / submission; credit scoring; document upload; multi-currency; amortization schedule
  table (just the summary in 7.1).
- Server-side calc / usage analytics; the other Phase 7 items (7.2 AI, 7.3 map, 7.4 journal, showroom,
  reels, telephony, omnichannel).

## 3. Design decisions (the four forks, resolved)

1. **Bank data = a DB seed table (read-only).** A `MortgageProgram` model, seeded, exposed via a public
   read endpoint. No runtime CRUD (updated by seed/migration); moderator CRUD + real feeds are deferred.
2. **Surface = listing-detail widget (prefilled price) + a standalone `/ipoteka` page.**
3. **Calc math = client-side** (Number annuity, instant as inputs change; an estimate). The bank table is
   the only backend piece.
4. **Input model = pick a program to prefill, then editable.** Picking a program fills rate + caps the
   term at `maxTermMonths` + enforces `minDownBps`; the buyer may also enter a custom rate/term.

## 4. Data model (additive migration)

One new table, seeded. No change to any existing table.

```prisma
/// A bank's mortgage program (7.1). Seeded, read-only in 7.1 (real feeds + moderator CRUD deferred).
/// Rates/percentages are basis points (Int); money is BigInt-as-string.
model MortgageProgram {
  id            String   @id @default(cuid())
  bankName      String
  programName   String
  /// Annual interest rate in basis points (1800 = 18.00%).
  rateBps       Int
  /// Maximum term in months (e.g. 240 = 20 years).
  maxTermMonths Int
  /// Minimum down payment in basis points of the price (1500 = 15%).
  minDownBps    Int
  /// Optional loan cap; null = uncapped.
  maxAmountSom  BigInt?
  active        Boolean  @default(true)
  /// Display order (ascending).
  position      Int      @default(0)
  createdAt     DateTime @default(now())

  @@index([active, position])
}
```

Migration name: `phase_7_1_mortgage` — one `CREATE TABLE` + its index. No `ALTER`/`DROP`.

**Seed:** add a curated `mortgagePrograms` array to `apps/api/prisma/seed-data.ts` and an idempotent
seed step in `seed.ts` (following the existing seed idiom — e.g. seed only when the table is empty).
The seeded rows are **illustrative sample programs** (plausible Uzbek-market parameters), NOT
authoritative live rates — real rates arrive via the deferred feed/CRUD.

## 6. Frontend (`apps/web`, FSD)

- **`shared/lib/mortgage.ts`** — a pure calculator (Number arithmetic):

```ts
export interface MortgageInput {
  priceSom: number;
  downSom: number;
  annualRateBps: number;
  termMonths: number;
}
export interface MortgageResult {
  principalSom: number;
  monthlySom: number;
  totalSom: number;
  overpaymentSom: number;
}

/** Annuity monthly payment. r=0 → straight division (no divide-by-zero). Estimate, rounded to som. */
export function computeMortgage({
  priceSom,
  downSom,
  annualRateBps,
  termMonths,
}: MortgageInput): MortgageResult {
  const principal = Math.max(0, priceSom - downSom);
  const r = annualRateBps / 10000 / 12; // monthly rate as a decimal
  const n = Math.max(1, Math.floor(termMonths));
  const monthly = r === 0 ? principal / n : (principal * r * (1 + r) ** n) / ((1 + r) ** n - 1);
  const monthlySom = Math.round(monthly);
  const totalSom = monthlySom * n;
  return {
    principalSom: principal,
    monthlySom,
    totalSom,
    overpaymentSom: Math.max(0, totalSom - principal),
  };
}
```

- **`features/mortgage/ui/mortgage-calculator.tsx`** — the calculator. Props: `{ initialPriceSom?: string }` (the listing price, when embedded). ## 7. Rulings & invariants (load-bearing)

- **R1 — client-side estimate, not exact money.** The calc uses Number arithmetic (property prices
  ≤ ~10¹² fit well inside `Number.MAX_SAFE_INTEGER` ≈ 9×10¹⁵; a mortgage rate is floating anyway). The
  result is a rounded **estimate** with a UI disclaimer — deliberately distinct from the exact-BigInt
  money used for real transactions. No BigInt is needed in the calculator.
- **R2 — public read-only programs.** `GET /api/mortgage/programs` is UNGUARDED (buyer-facing), returns
  only `active` programs ordered by `position`; there is NO write route (seed-only).
- **R3 — validation.** `downSom < priceSom` (principal > 0; else the UI shows nothing to finance);
  `termMonths ≥ 1`; when a program is picked, `term ≤ maxTermMonths` and `down% ≥ minDownBps` (a hint,
  not a hard block, on the custom path); `r === 0 → monthly = principal / n` (no divide-by-zero).
- **R4 — additive-only.** One new table + an idempotent seed; no existing-table change; no auth/org
  surface touched.
- **R5 — money display.** The calc returns Numbers; the UI stringifies (`String(Math.round(x))`) for
  `formatPriceSom(x, 'SALE')` to reuse the money formatter. `maxAmountSom` DTO is BigInt-as-string.
